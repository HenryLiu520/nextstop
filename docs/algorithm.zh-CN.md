# NextStop：规划与修复算法

[English](algorithm.md) · **简体中文** · [繁體中文](algorithm.zh-TW.md)

一天如何从固定课表规划出来，以及现实发生偏移时那份计划如何被修复。这是一份设计文档。原型里的 planner 只是一个 stub（第 9 节），所以这里没有任何实测结论。它要支撑的主张只有一句话：出现偏离时，系统改动尽可能少的站点，并且比一次完整重算改得更少。

## 1. 问题陈述

**输入。**

| 符号 | 输入 | 内容 |
|---|---|---|
| `A` | anchors | 固定安排，含楼、房间、开始、结束 |
| `G` | gaps | 由 `A` 推导出的空闲区间 |
| `W` | walk matrix | 楼对之间的分钟数，按学习到的步行系数缩放 |
| `R` | availability | `free(room, t0, t1)`，来自已有的 availability engine |
| `P` | profile | 参数：时间容差、楼容差、buffer、步行系数、用餐窗口 |
| `L` | location | 一次定位读取，仅在 reveal 时 |
| `D` | deviation | `delay(min)`、`change(stop)`、`skip(anchor)`、`arrive(stop)` |

**输出。** 首个 anchor 与末个 anchor 之间的有序站点序列。一个站点是 `(type, purpose, building, room, start, end)`，type 取四种之一：`study`、`eat`、`meet`、`transit`。
楼与楼之间的步行是一个 `transit` 站点，同一栋楼内部的步行不构成站点。没有 `wait` 类型：每个算出的 gap 要么被填满，要么并入相邻站点。

**约束。**

1. anchor 是权威的。planner 从不移动、缩短或质疑它。
2. 两个站点不重叠，且某个 anchor 之前的最后一个站点结束得足够早，能走过去。
3. 楼与楼之间的移动永远要付出代价，要么作为一个 `transit` 站点，要么算在 gap 之内。
4. 只有当 `free(room, t0, t1)` 在整个区间成立时，站点才占用该房间。
5. `arrive(t)` 是终局。过去的站点被截断，绝不重新规划。
6. 出勤变更属于学生。planner 从不产生这种变更。
7. 已提交的计划是每一次比较的基准（第 3 节）。

**成功标准。** 四个数字，都可测，都还没测。

| 指标 | 定义 | 方向 | 状态 |
|---|---|---|---|
| 操作次数 | 跟随一天所需的手势数 | 不增加 | 未插桩 |
| 执行率 | 未经用户替换即到达开始时间的计划站点占比 | 越高越好 | 未插桩 |
| 每次修复改动的站点数 | 每次偏离中 `(purpose, building, start)` 发生移动的站点数 | 1 到 2，低于完整重算 | 未插桩 |
| 相对完整重算的差值 | 同一偏离下改动的站点数与未受影响的执行率 | 修复必须胜出 | 开关已定义，未实现 |

第四个是承重的那个。它不是延迟数字，是稳定性数字：最小修复是否比重新求解全部留下更多的原样。同一次偏离必须能在两条路径上重放，否则这个比较毫无意义。

## 2. 四个层

```
+--------------------------------------------------------------------+
| L1  ANCHORS    fixed, authoritative, never questioned              |
|      09:00 COMP1100 CSIT   11:00 MATH1013 KB   13:00 COMP2100 CSIT |
+--------------------------------------------------------------------+
                     | gaps between commitments
                     v
+--------------------------------------------------------------------+
| L2  FREE TIME  gap = next_start - prev_end - walk - buffer         |
|                usable if >= min_stop, else merged, never a wait    |
+--------------------------------------------------------------------+
                     | usable intervals
                     v
+--------------------------------------------------------------------+
| L3  FILL       one stop per interval: study / eat / meet           |
|                transit between buildings, no wait type             |
+--------------------------------------------------------------------+
                     | a deviation is observed
                     v
+--------------------------------------------------------------------+
| L4  REPAIR     keep what still holds, re-solve the broken window,  |
|                then check the neighbouring stop                    |
+--------------------------------------------------------------------+
```

**L1 Anchors。** 课表读一次，并为这一天冻结。它不是偏好，也不是 planner 可以纠正的东西。即使学生迟到，anchor 仍然按它自己的时间开始：变化的是学生的可用性，不是课表。正是这种不可变性让其余部分可处理，因为每个窗口于是都有了两堵固定的墙。

**L2 空闲时间。** 每个 gap 是一个 anchor 的结束到下一个 anchor 的开始之间的区间，减去走到下一栋楼的步行时间，再减去一个 buffer。余量只有达到一个站点的最短时长（`min_stop`，默认 15 分钟）才可用。达不到就把这个 gap 并入相邻区间，而不是产出一个残桩站点或一个空块。
这一层只输出时长，所以可以单独测试。

**L3 填充。** 每个可用区间得到一个站点，而站点的结束时间由它后面的东西推导出来，不是自由选择的。类型来自目的优先级（本来会被错过的用餐窗口优先级高于学习），地点来自 availability engine 加步行矩阵。填充每天在 reveal 时运行一次，之后计划只读，直到出现偏离。正是这一层让输出成为一个序列而不是一个集合：为 10:00 选定的站点决定了 11:00 时学生站在哪栋楼里。区间里填哪一间房由另一套过程决定，写在 [`room-scoring.zh-CN.md`](room-scoring.zh-CN.md)。

**L4 修复。** 任何偏离从这里进入。修复识别出哪些站点相对已提交计划不再成立，其余原样保留，只在破损窗口内部重新求解，然后检查下一个站点，确认修法没有溢出窗口。修复是唯一可以写入已发布计划的层，而且它总会写入一条 undo 记录。

## 3. 同一性判据

一个候选站点 `s'` 与已提交站点 `s` 是同一件事，当且仅当以下三条全部成立。

1. **目的不变。** 同一门课的学习块，`meet` 的是同一组人，吃饭仍然是吃饭。目的是 `(type, subject_ref)`：在另一栋楼学 COMP1100 是同一个目的，换成学 COMP2100 就不是。
2. **地点是同一栋楼，或在步行容差之内。** 同一 building id，或 `walk(s'.building, s.building) <= building_tolerance`（默认 4 分钟）。两分钟外的另一栋楼算同一个地点。十二分钟外的不算。
3. **开始时间相差不超过时间容差。** `abs(s'.start - s.start) <= time_tolerance`（默认 15 分钟）。

三条都要，不是其中任意两条。只看目的，一天可以任意滑走。只看地点，一个学习块可以变成一顿午饭。只看时间，学生可能最后待在另一栋楼里，却被告知什么都没变。

基准永远是已提交的计划，也就是学生实际看到的那个版本。拿上一版内部候选去比较会容许缓慢漂移：每次修复 14 分钟，每次都报告无变化，到午饭时已经差了一个小时。

判据之所以存在，是因为修复需要一个停止条件。没有同一性判断，每一次偏离都得把下游每个站点当作可疑，修复就退化成多走几步的重算。判据是决定修复做多少工作的闸门，所以它的两个容差是系统里最承重的参数。它们是参数，不是常量，第 8 节就按参数对待它们。

一个刻意的后果：已确立的站点永不重新优化，即使存在严格更好的位置。计划不是最优的，是稳定的。一个记得「10:00，CSIT 105」的学生发现它还在原处，得到的是更好的计划给不了的东西。代价是永久的局部次优，这是知情的取舍。

## 4. 修复流程

```text
repair(plan, deviation):
    observe = (t_now, building_now)                # the deviation, as reported
    W       = window(plan, observe)                # first broken stop to last broken stop
    keep    = [s for s in plan if same_thing(s, committed[s])]
    broken  = plan - keep
    if broken is empty: return plan
    for rank in [SHIFT, ROOM, BUILDING, CANCEL]:   # attendance is not a planner rank
        cand = solve(W, keep, rank)
        if feasible(cand): break
    cand = expand_until_stable(W, cand)            # at most 2 expansions
    return commit(cand, undo_log)
```

1. 两个值进，一份计划出。这次调用可重放，第 1 节的比较之所以可能，全靠这一点。
2. `observe` 把事件归一成一个时间和一栋楼。20 分钟的超时和一次「我迟到了」的点击产生同一个观察，所以修复只有一个入口。
3. `W` 是破损窗口：从第一个再也站不住的站点，到观察使其失效的最后一个站点。anchor 是窗口的墙，从不是窗口的成员。
4. `keep` 对每个站点应用第 3 节的三条测试，基准是已提交版本。
5. `broken` 是补集。在典型的偏离里它有一到两个成员。
6. 没有破损站点，说明计划仍然成立，于是什么都不写。这一情形很便宜。
7. 第 5 节的阶梯按顺序走。每一级是一次独立的求解，第一个可行的级别胜出，走查到此为止。
8. `solve` 只在 `W` 之内枚举候选位置。它从来看不到一天的其余部分，这正是它成本受限的原因。
9. 接受某一级之前先测可行性。不可行的候选被丢弃，接着试下一级。
10. 邻居检查只问一个问题：`W` 的新边界是否把下一个保留站点推过时间容差，或破坏走到它的那段步行。级联在接缝处被抓到。
11. 如果会，窗口扩大一个站点并重新求解，最多两次。之后调用方回退到对剩余一天的完整重规划，这是诚实且少见的。
12. `commit` 发布计划并追加一条 undo 记录。一次糟糕的修复只花一次点击，不花一天。

## 5. 成本顺序

修复爬这道阶梯，停在第一个能给出可行窗口的级别。顺序是字典序，不是加权和。加权和会让三个便宜动作压过一个昂贵动作，而学生体验到的是那个昂贵动作。

| 级别 | 动作 | 学生注意到什么 | 谁可以触发 | 可撤销 |
|---|---|---|---|---|
| 1 | 把边界平移 5 到 10 分钟 | 同一个站点，同一个房间，分钟挪了 | system | 是 |
| 2 | 换房间，同一栋楼 | 同一栋楼同一时间，房间号不同 | system | 是 |
| 3 | 换楼 | 另一栋楼，步行更久 | system | 是 |
| 4 | 取消整个站点 | 一个站点消失，它的时间被并入 | system | 是 |
| 5 | 改出勤 | 这门课被视为空闲，仅对该学生 | user only | 是 |

由偏离本身强制的平移不算在 planner 头上。如果学生迟了 20 分钟，站点的开始时间移动是因为学生移动了，不是 planner 选择要移。阶梯给 planner 在现实之上额外添加的东西定价。这也是级别 1 封顶 10 分钟的原因：更大的平移意味着这个站点正在被重新推导，那属于窗口求解。

级别 4 是取消，不是等待。腾出来的区间不会变成一个空块，它被并入相邻站点或并入步行。一个被取消的站点如果留下可见的死时间，那是违反第 1 节约束 3 的 bug。

级别 5 永不由 planner 进入。出勤是只有学生能主张的事实。系统会围绕一次缺课来规划，但永远不会决定一次缺课。

## 6. 复杂度

`n` 是一天的站点数（实践中 4 到 8）。`m` 是每个站点的候选地点数（几十到低三位数）。`k` 是破损站点数（典型 1 到 2）。`w` 是破损窗口内的站点数（典型 2 到 4）。

| 例程 | 成本 | 何时运行 |
|---|---|---|
| 完整规划 | `O(n * m)` | reveal 时，每天一次 |
| 修复 | `O(k * m * w)` | 每次偏离 |
| 邻居检查 | `O(1)` | 每次修复之后 |
| 最坏情况修复 | `O(n * m)` | 偏离发生在当天第一个站点时 |

诚实的比较。完整重算是 `O(n * m)`。修复是 `O(k * m * w)`，比它好 `n / (k * w)` 倍。取 `n = 6`、`k = 1`、`w = 3`，这个倍数是 2。偏离发生得早时，窗口覆盖剩余一天的大部分，倍数趋近 1。最坏情况下没有渐近优势，本文档也不主张有。

绝对数字两边都很小。六个站点对上百个候选房间，是几百次可行性检查，每次都由一个预计算的区间索引回答。没人会注意到那几毫秒。最小修复的理由不是速度，是改动的站点数。完整重算可能重新排序每个房间、重新推导每个时长，于是它的输出在本来没问题的地方也不同，每一处不同都要学生重读自己的一天。

## 7. 一个算例

示例说明，不是实测结果。数字是为了能走通而选的，能产出它们的 planner 就是第 9 节描述的 stub。

anchor：09:00 到 10:00 COMP1100 在 CSIT，11:00 到 12:00 MATH1013 在 KB，13:00 到 14:00 COMP2100 在 CSIT，16:00 到 17:00 PHYS1200 在 CSIT。CSIT 到 KB 步行 7 分钟，buffer 为 3。

| # | 类型 | 地点 | 已提交 | 修复后 |
|---|---|---|---|---|
| S1 | study | CSIT 105 | 10:03 到 10:47 | 10:23 到 10:46，已改动 |
| S2 | transit | CSIT 到 KB | 10:47 到 10:56 | 10:46 到 10:53，保留 |
| S3 | eat | KB food court | 12:05 到 12:42 | 未变，保留 |
| S4 | transit | KB 到 CSIT | 12:42 到 12:51 | 未变，保留 |
| S5 | study | CSIT 227 | 14:05 到 15:50 | 未变，保留 |
| S6 | study | CSIT 227 | 17:05 到 18:20 | 未变，保留 |

10:20 时学生报告超时 20 分钟，人仍在 CSIT。50 分钟的可用 gap 变成 33 分钟，而走到 KB 的那一段不能挪，因为 MATH1013 是 anchor。

同一性测试。S1 不能在 10:03 开始，因为学生到 10:20 才空闲，这已经比计划开始晚了 17 分钟，超出 15 分钟容差，所以 S1 破损。
S2 保持了它的目的、它的楼对，以及一分钟以内的开始时间，所以它被保留。S3 到 S6 位于窗口之外，被保留。

阶梯在跨 S1 与 S2 的窗口内走查，左边以 10:20 为界，右边以 11:00 为界。级别 1 适用：同一房间里的同一个学习站点，边界调整，容得下 23 分钟学习，步行与 buffer 仍然完整。级别 2 到 4 从未到达。

改动的站点：1。邻居检查通过，因为下一个保留站点是 anchor，走到它的步行仍然成立。

作为对照，同一次偏离的完整重算会重新推导全部四个 gap。在这个示例里它落在三处不同：上午的学习挪到 KB 一侧，午饭站点因为求解器不再看到原来的边界而缩到更短的窗口，下午的学习换了房间因为 availability 快照被重新排序。改动的站点：3。结果纸面上并不更好，实践中却明显更扰人，而第 1 节的比较正是为量这个量而设计的。

## 8. 失效模式

**过松的判据。** 放宽三条测试，大多数候选都能匹配，计划就在没人察觉中漂移。随之有两种形态：学生走到 CSIT 105 发现它是空的，因为那个块在楼内悄悄挪了位置，或者一个学习块长大吃掉了午饭，因为目的和地点都匹配，只有时长变了。对两者的防护是，同一性以已提交计划为基准度量，且站点保持它的类型与科目。

**过紧的判据。** 收窄容差，普通偏离就会打断下游的一切。学生迟到 8 分钟，整个下午被重新求解。症状是执行率崩塌，同时每次修复改动的站点数逼近完整重算的数值，于是修复层变得毫无意义。

**容差敏感性。** 两个容差都会牵动全部四个指标，所以它们是扫描的，不是固定死的。`time_tolerance` 取 5，一次 6 分钟的轻推就变成破损站点。取 30，不同的站点合并成同一个身份，一天可以每个事件滑掉半小时。还有一条一致性约束：级别 1 最多平移一个站点 10 分钟，所以 `time_tolerance` 低于 10 会让最便宜的 planner 动作与同一性测试自相矛盾，产出报告了意外变动的修复。这一对必须满足 `time_tolerance > max shift at rank 1`。`building_tolerance` 的单位是步行分钟，抬高它会让跨楼的短跳变成免费，从而悄悄废掉同楼规则。

**级联。** 一次修复可能把下一个站点推过容差，进而打断再下一个。邻居检查抓一步，扩张循环抓两步，之后剩余的一天被完整重规划。那个回退是对最小性主张的真实失败，所以单独计数并报告，而不是藏进改动站点平均值里。循环会终止，因为每次扩张都严格增大窗口，而窗口被计划所限。

**永久的局部次优。** 已确立的站点永不重新优化，所以一个变吵或变满的房间会留下，只要它仍算同一件事。补救办法是用户自己的「换掉这一个」动作，那是用户发起的打断，不是修复。

**陈旧的 availability。** availability 在 reveal 时读取，之后就被信任。如果房间在 reveal 与到达之间被占满，计划就是错的，直到用户报告。系统不做轮询，所以这是被接受的，而不是被解决的。

**超时超过 gap。** 超过 gap 的延迟绝不能用缩短 anchor 来吸收。anchor 胜出，站点被取消，下一个 anchor 迟到加入。为了塞进一个站点而压缩 anchor 的 planner 是违约的。

## 9. 未实现的部分

原型里的 planner 是一个 stub。它读 anchor，算 gap 时长，并在每个可用区间放一个时长固定的学习站点。它不查询房间，不走成本阶梯，不跑同一性测试，也没有修复路径。对它调用 `repair` 会返回你交给它的那份计划。

已存在：anchor 摄入、gap 算术、基于课表的 availability engine、楼到楼的步行矩阵、四状态状态机，以及偏离事件。还不存在：窗口求解器、阶梯、邻居检查、代码里的同一性测试，以及第 1 节四个指标的插桩。

所以本文档里的每个数字要么是设计参数，要么是示例，第 7 节因此自带警告。修复比完整重算改动更少站点这一主张仍是假设。它是比较开关首先要测的东西，在任何界面工作压到它上面之前。

同样刻意缺席的：自动出勤变更、容差的多天学习（它们从默认值起步），以及小群组在 claim 与 retract 路径之外的任何预订。这些是设计的边界，不是原型的缺口。
