# 自習室評分

[English](room-scoring.md) · [簡體中文](room-scoring.zh-CN.md) · **繁體中文**

一天裡的一個空檔怎麼選出一間房。問題故意問得很窄：兩節課之間那段時間，哪一間值得走這一趟。

各節按計算的先後排。第 0 步建一張常駐裝置的表。第 1 步拿掉根本服務不了這個空檔的房間。第 2 步給兩個隨小時變化的事實打分。第 3 步把兩個分數按視窗長度加權合成。第 4 步取第一名，另留三間給「換一個」用。

本文有兩部分處於不同狀態。靜態分已經實現，讀服務端的評價表。拒絕模型、動態分與融合是設計，有取值，沒有上線程式碼。

## 01 流程

```
第 0 步  靜態表 S        一間房一行，偏好變化或拒絕時才寫
第 1 步  硬過濾          整段空閒、能進、非剛離開、走得到
第 2 步  動態分 D        走過去多久、能坐多久
第 3 步  融合 F          權重隨視窗長度滑動
第 4 步  取第一          選中的一間，另留三間給「換一個」
```

每一步要麼縮小候選集，要麼加一個數。管道里沒有哪一步讀第二次時鐘，所以同樣的輸入重跑一遍還是同一間房。

**輸入。**

| 記號 | 輸入 | 內容 |
|---|---|---|
| `R` | 候選集 | 全部自習室，約 200 間，常駐裝置 |
| `W` | 視窗 | `t0` 與 `t1`，單位分鐘 |
| `p` | 前一錨點 | 結束時刻與樓棟，前面沒有課則為空 |
| `n` | 後一錨點 | 開始時刻與樓棟，後面沒有課則為空 |
| `u` | 使用者畫像 | 偏好、到訪歷史、拒絕記錄 |
| 快照 | 可用性 | `W` 內每間房的空閒區間，帶抓取時間 |

**輸出。** 一間選中的房，接下來三間各帶一條理由，以及每個候選的分項得分。卡片文案和除錯檢視讀的是同一份分項得分。

## 02 靜態分 S

七個因子，每一個都站在「一個人走進一間房坐下來」的角度。權重合計 1.00。

| 因子 | 它回答什麼 | 權重 |
|---|---|---|
| 熟悉度 | 這棟樓我來過沒有，來過幾次 | 0.20 |
| 安靜程度 | 坐進去吵不吵 | 0.20 |
| 桌面與座位 | 電腦和書攤不攤得開 | 0.15 |
| 插座 | 座位邊有沒有電 | 0.15 |
| 空調 | 香港的夏天在這種屋裡能不能過 | 0.10 |
| 空間大小 | 40 到 80 座最舒服，兩頭都不對 | 0.10 |
| 採光 | 有沒有外窗，白天開不開燈 | 0.10 |

```
S = Σ w_i × f_i
```

熟悉度與常去樓棟是同一件事，所以只佔一個權重。到訪次數封頂十次，一棟樓吃不下全部分數。

**三個因子不進表。** 用途匹配由安靜程度回答，找自習室的人要的就是一個安靜的位置。容量並進空間大小，40 到 80 座給滿分。樓層並進行程時間，換一層樓就是多等一次電梯。

### 六個可評價因子怎麼量化

學生寫評價時給其中六個因子打 1 到 10 的整數。服務端把每個因子單獨存一列，評分不從正文裡解析。

```
f_i = 該因子評價均值 / 10        缺項時按剩餘權重歸一
```

評價裡的總分只用於展示，不進排序。一個數字說不出是哪一項動了。熟悉度在服務端被去掉，因為它屬於某一個賬號，共用介面沒有賬號可讀。

六個權重重新歸一到 0.80，`GET /api/rooms/overview` 報的就是這個結果：

| 因子 | 表內權重 | 歸一後 |
|---|---|---|
| 安靜程度 | 0.20 | 0.25 |
| 桌面與座位 | 0.15 | 0.1875 |
| 插座 | 0.15 | 0.1875 |
| 空調 | 0.10 | 0.125 |
| 空間大小 | 0.10 | 0.125 |
| 採光 | 0.10 | 0.125 |

介面按十分制報結果，也就是 `S` 乘十。沒有評價的房間報空分，介面打一條橫線。當成零分會把它壓進一個它本來沒進的榜。

### 表常駐在裝置上

200 行，二十多 KB，存在 IndexedDB，按偏好雜湊與房間修訂號做鍵。只有三個事件會寫它。

- 偏好變化：全表重算 `base`，`n_eff` 原封不動，一次 `O(200)`。
- 拒絕發生：只寫那一行。`n_eff += w_kind`，`nat = now`。
- 房間屬性更新：只重算變動的那批。

```js
staticTable = {
  prefHash: "9f2c…",
  roomVersion: 14,
  rows: {
    kb227: { base: 0.58, visits: 7, n_eff: 1.8, nat: 1793 },
    lib3f: { base: 0.82, visits: 3, n_eff: 0.0, nat: 0 }
  }
}
```

衰減懶計算。讀取時算 `n_eff_now = n_eff × e^(−(now − nat) / 21 天)`。落盤時順手把值寫回。後臺不跑計時器。

已釋出的計劃留著它已經選定的房間。表立刻更新。計劃在下一個揭開時刻才讀新值，守住 [`algorithm.zh-CN.md`](algorithm.zh-TW.md) 裡「釋出之後只讀」那條規則。

## 03 拒絕

拒絕不進因子表，它是掛在靜態分上的長期折扣。折扣在讀取分數時生效。

```
n_eff = Σ_j exp(−Δt_j / 21 天)        每次拒絕計一次，21 天衰到 37%
S'    = S × (1 − 0.12)^n_eff          每次有效拒絕乘 0.88
```

| 有效拒絕次數 | 剩餘比例 |
|---|---|
| 1 | 88% |
| 2 | 77% |
| 3 | 68% |
| 5 | 52% |
| 8 | 36% |

乘法給出三個性質，每一個都用得上。每拒一次，分數降一點，這正是這個動作的意思。拒得多了房間會沉下去，同時留在零以上，翻新過的房間還能回來。撤銷一次，分數回來一檔，改主意不必清空歷史。

點「不喜歡」記 1.0 次，換到別的房間記 0.5 次。到了又很快離開記 0.3 次。三十天內的重複拒絕自然疊加，不需要額外的加成係數。

## 04 動態分 D

兩個因子，權重合計 1.00，都讀視窗和兩個錨點。

### 行程時間

`t_prev` 是前一站走到房間的時間，`t_next` 是房間走到後一站的時間。缺一邊按 0 計。

```
slack = W.t0 − p.end − 2 分鐘          緩衝從頭上扣
total = t_prev + t_next
κ     = clamp(0.6 × slack, 3, 12)
T     = exp(−total / κ)
```

slack 決定一分鐘走路值多少。只剩五分鐘的學生 `κ` 是 3，走三分鐘就掉到 0.37。有四十多分鐘餘量時 `κ` 到 12，走五分鐘還有 0.66。時間餘量就藏在這個因子裡，表裡沒有單獨的一項。

兩道判斷管可行性，都在算分之前。到得了，並且剩下至少五分鐘能坐，即 `t_prev ≤ 視窗分鐘 − 5`。走到下節課也來得及，即 `t_next ≤ 後課開始 − t1 − 2`。任意一道不過，候選直接出局。

### 連續可用

```
horizon = 從 t0 起連續空閒的分鐘數
C       = min(horizon / 120, 1)
```

連續空 120 分鐘得 1.0，半小時得 0.25。相鄰視窗落在同一間房加 0.1，封頂 1.0。

```
D = 0.65·T + 0.35·C
```

走路佔大頭，因為它是學生此刻真金白銀付出的那筆成本。連續可用決定這一次坐下來值不值。

## 05 融合

```
wD = clamp(0.40 + 0.25 × (1 − 視窗分鐘 / 120), 0.40, 0.65)
wS = 1 − wD
F  = wS × S' + wD × D
```

| 視窗 | wS（房間本身） | wD（當下遠近） | 讀法 |
|---|---|---|---|
| 20 分鐘課間 | 0.35 | 0.65 | 先解決來不來得及 |
| 60 分鐘 | 0.475 | 0.525 | 遠近與舒適各半 |
| 120 分鐘及以上 | 0.60 | 0.40 | 開始挑剔房間 |

**排序。** 按 `F` 降序，相同則比 `S'`，再相同按房間編號升序。同樣的輸入永遠給出同樣的輸出，出現分歧就去查畫像或快照。

```js
function pickStudyRoom(W, p, n, u, rooms, snapshot) {
  const table = ensureTable(u.prefHash, snapshot.roomVersion)
  const cands = []
  for (const r of rooms) {
    if (!passesFilters(r, W, p, n, u, snapshot)) continue
    const row = table.rows[r.id]
    const S2 = row.base * Math.pow(1 - 0.12, effReject(row, now))
    const total = walk(p, r) + walk(r, n)              // 缺一邊按 0
    const k = clamp(0.6 * slack(W, p), 3, 12)
    const T = Math.exp(-total / k)
    const C = Math.min(contiguousFree(r, W.t0) / 120, 1)
    const D = 0.65 * T + 0.35 * C
    const wD = clamp(0.40 + 0.25 * (1 - len(W) / 120), 0.40, 0.65)
    cands.push({ r, F: (1 - wD) * S2 + wD * D, S2, T, C, D })
  }
  cands.sort((a, b) => b.F - a.F || b.S2 - a.S2 || a.r.id - b.r.id)
  return { pick: cands[0], swaps: cands.slice(1, 4) }
}
```

每個視窗 `O(|R|)`，把候選集過一遍。一天 8 個視窗、200 間房，約 1600 次評估，手機端落在毫秒預算之內。

## 06 算例

視窗 11:00 到 12:00。前一節 10:45 在 KB 223 下課，所以 slack 是 13 分鐘，`κ` 是 7.8。後一節 14:00 在 CPD，只用來判斷走不走得到。視窗 60 分鐘，所以 `wS` 是 0.475，`wD` 是 0.525。

| 房間 | S | 有效拒絕 | S' | 步行 | T | C | D | F |
|---|---|---|---|---|---|---|---|---|
| KB 227 | 0.58 | 2.0 | 0.45 | 7 分鐘 | 0.41 | 0.50 | 0.44 | 0.45 |
| LIB 3F | 0.82 | 0 | 0.82 | 21 分鐘 | 0.07 | 0.67 | 0.28 | **0.54** |
| RHT 302 | 0.69 | 0 | 0.69 | 14 分鐘 | 0.17 | 0.50 | 0.29 | 0.48 |

LIB 3F 房間最好，拿到第一，代價是走 21 分鐘。KB 227 就在樓下，身上壓著兩次拒絕，房間本身也一般，排在第三。

這個結果是一次取捨，取房間還是取走路。視窗縮到 20 分鐘，`wD` 升到 0.65，slack 變小所以 `κ` 掉到 3，KB 227 就翻上來。同一批房間、同一個人、兩個視窗、兩個答案。權重的存在就是為了做出這個區別。

## 07 引數

| 引數 | 預設 | 範圍 | 作用 |
|---|---|---|---|
| 拒絕折扣 | 每次 0.88 | 0.82 到 0.94 | 被拒一次降多少 |
| 拒絕半衰 | 21 天 | 7 到 60 | 舊拒絕多久淡掉 |
| `κ` 係數 | 0.6 × slack | 夾在 3 與 12 | 時間懲罰的陡峭程度 |
| `C` 滿分段 | 120 分鐘 | 60 到 180 | 多長算坐得下去 |
| `wD` 區間 | 0.40 到 0.65 | 由視窗決定 | 遠近與房間本身的相對分量 |
| 熟悉度封頂 | 10 次 | 5 到 20 | 防止只去老地方 |
| 觀測門限 | 3 次評分 | 3 到 10 | 滿幾次才用評價均值替換預設值 |

每一行都是「一個引數 + 一個計數器」的形態。滿三次觀測才替換預設值，使用者手動改過就清零，學習重新開始。

這些引數是設計值，背後沒有實測。demo 裡把 `S'`、`T`、`C`、`D`、`F` 都列印出來，排序可以手算核對。

## 失效場景

**老地方鎖死。** 熟悉度封頂 10 次，權重 0.20，習慣最多把一間房抬起來 0.2。位置與安靜壓得過它。

**拒絕把房間打死。** 乘法結果留在零以上，八次有效拒絕後仍留 36%。翻新過的房間還能回到備選。

**視窗太短填不下。** 視窗小於 25 分鐘就不排自習。規劃器把它並進相鄰視窗，或者跳過。

**快照過期。** `contiguousFree` 讀的是快照，快照自帶抓取時間。超過十分鐘未重新整理，`C` 減半，卡片標「未核實」。

**某個因子沒有資料。** 沒有資料的因子不進計算，它的權重攤給其餘項。一間房完全沒有評價就報空分，介面打橫線。

## 與計劃層的關係

評分只回答一個問題，這個視窗放哪間房。視窗放什麼、放多久、幾點該走，由計劃層決定。換房不動時間，改時間不動房，兩個動作各自帶著自己的撤銷記錄。

靜態表屬於房間本身。[`adr/0005`](adr/0005-room-attributes-are-scored-on-the-server.zh-TW.md) 把這張表讀的六個屬性放在服務端，客戶端按修訂號快取。
