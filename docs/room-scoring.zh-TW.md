# 自習室評分

[English](room-scoring.md) · [簡體中文](room-scoring.zh-CN.md) · **繁體中文**

一天裡的一個視窗怎麼選出房間。這是一份設計文件。原型裡的規劃器仍然是樁，所以下面每個數字都是設計值，或者來自算例。

## 引言

評分只回答一個問題，這個視窗、這名學生，選哪一間房。視窗放什麼、放多久，由計劃層決定。評分讀三樣東西：視窗本身，從前一站走到房間的時間，從房間走到後一站的時間。

**輸入。**

| 符號 | 輸入 | 內容 |
|---|---|---|
| `R` | 候選集 | 全部自習室，約 200 間，存在裝置上 |
| `W` | 視窗 | `t0` 與 `t1`，單位分鐘 |
| `p` | 前一個錨點 | 結束時刻與樓棟，前面沒有課則為空 |
| `n` | 後一個錨點 | 開始時刻與樓棟，後面沒有課則為空 |
| `u` | 使用者畫像 | 偏好、到訪歷史、拒絕記錄 |
| 快照 | 可用性 | `W` 內每間房的空閒區間，帶抓取時間戳 |

**輸出。** 一間選中的房，接下來三間各帶一條理由，以及每個候選的分項得分。卡片文案和除錯檢視都讀這份分項得分。

### 硬過濾

四個判斷跑在任何分數之前，過濾就到這裡為止。

```
free(r, W)        整段空閒
allowed(u, r)     這個身份能進
r != last_room    不是剛離開的那間
reachable(r, W)   走得過去，判據見「行程時間」
```

座位數不進過濾，一個學生總能在樓裡找到位置。真正的問題是這間房值不值得走一趟。

## 固態表

七個因子，每一個都站在「一個人走進一間房坐下來」的角度。權重合計 1.00。

| 因子 | 衡量什麼 | 打分方式 | 權重 |
|---|---|---|---|
| 熟悉度 | 這名學生反覆回去的那棟樓、那幾間房 | `min(該樓到訪次數 / 10, 1)` | 0.20 |
| 安靜程度 | 這間房本身有多吵 | 靜音區 1.0，普通 0.65，討論區 0.35，再按實時佔用率下調 | 0.20 |
| 桌面與座位 | 電腦和書能不能並排攤開 | 桌面寬 90cm 及以上得 1，尺寸每小一檔就往下減 | 0.15 |
| 插座 | 座位邊有沒有電 | 每座都有 1.0，沿牆有 0.5，沒有 0 | 0.15 |
| 空調 | 香港的夏天 | 有 1.0，沒有 0 | 0.10 |
| 空間大小 | 太擠難受，太空也不安 | 40 到 80 座滿分，兩端各減半 | 0.10 |
| 採光 | 有窗，白天不用開燈 | 外窗 1.0，天井窗 0.5，無窗 0 | 0.10 |

```
S = Σ_i w_i × f_i
```

熟悉度與常去樓棟是同一件事，合併成一項。到訪次數封頂 10 次，一棟樓吃不下全部分數。

### 表外的三個因子

**用途匹配。** 找自習室的學生要的是一個安靜的位置。安靜因子已經把這個問題答了。

**容量貼合。** 一個人不會去數房間的座位夠不夠。容量作為寬敞度的代理，出現在空間大小裡。

**樓層偏好。** 樓層真正影響的是等電梯的時間，等電梯就是走路。行程時間比單獨一個偏好算得更準。

### 表常駐在裝置上

200 行，二十多 KB，存在 IndexedDB，按偏好雜湊與房間修訂號做鍵。只有三個事件會寫它。

- 偏好變化：全表重算 `base`，`n_eff` 原封不動，一次 `O(200)`。
- 拒絕發生：只寫那一行。`n_eff += w_kind`，`nat = now`。
- 房間屬性更新：只重算變動的那批。

```js
staticTable = {
  prefHash: "9f2c…",
  roomVersion: 14,
  rows: {
    kb227: { base: 0.58, visits: 7, n_eff: 1.8, nat: 1793 },
    lib3f: { base: 0.82, visits: 3, n_eff: 0.0, nat: 0 }
  }
}
```

衰減懶計算。讀取時算 `n_eff_now = n_eff × e^(−(now − nat) / 21 天)`。落盤時順手把值寫回。後臺不跑計時器。

已釋出的計劃留著它已經選定的房間。表立刻更新。計劃在下一個揭開時刻才讀新值，守住 [`algorithm.zh-CN.md`](algorithm.zh-CN.md) 裡「釋出之後只讀」那條規則。

## 拒絕

拒絕不進因子表，它是掛在固態分上的長期折扣。折扣在讀取分數時生效。

```
n_eff = Σ_j exp(−Δt_j / 21 天)        每次拒絕計一次，21 天衰到 37%
S'    = S × (1 − 0.12)^n_eff          每次有效拒絕乘 0.88
```

| 有效拒絕次數 | 剩餘比例 |
|---|---|
| 1 | 88% |
| 2 | 77% |
| 3 | 68% |
| 5 | 52% |
| 8 | 36% |

乘法給出三個性質，每一個都用得上。每拒一次，分數降一點，這正是這個動作的意思。拒得多了房間會沉下去，同時留在零以上，翻新過的房間還能回來。撤銷一次，分數回來一檔，改主意不必清空歷史。

點「不喜歡」記 1.0 次，換到別的房間記 0.5 次。到了又很快離開記 0.3 次。三十天內的重複拒絕自然疊加，不需要額外的加成係數。

## 動態分

兩個因子，權重合計 1.00，都讀視窗和兩個錨點。

### 行程時間

`t_prev` 是前一站走到房間的時間，`t_next` 是房間走到後一站的時間。缺一邊按 0 計。

```
total = t_prev + t_next
κ     = clamp(0.15 × 視窗分鐘, 3, 12)
T     = exp(−total / κ)
```

視窗決定一分鐘走路的價格。20 分鐘的視窗把 `κ` 壓到 3，走 3 分鐘只剩 0.37。兩小時的視窗把 `κ` 抬到 12，走 5 分鐘還有 0.66。走路吃的是視窗本身，視窗越長，越吃得消遠一點的房間。

時間餘量就藏在這個因子裡。視窗越緊，同樣的距離扣得越狠，再單列一個餘量因子只是把同一件事寫兩遍。

兩道判斷管可行性。到得了，並且剩下至少五分鐘能坐，即 `t_prev ≤ 視窗分鐘 − 5`；走到下節課也來得及，即 `t_next ≤ next_start − t1 − 2`。任意一道不過，候選直接出局。

### 連續可用

```
horizon = 從 t0 起連續空閒的分鐘數
C       = min(horizon / 120, 1)
```

連續空 120 分鐘得 1.0，半小時得 0.25。相鄰視窗落在同一間房加 0.1，封頂 1.0。

```
D = 0.65·T + 0.35·C
```

走路佔大頭，因為它是學生此刻真金白銀付出的那筆成本。連續可用決定這一次坐下來值不值。

## 融合

```
wD = clamp(0.40 + 0.25 × (1 − 視窗分鐘 / 120), 0.40, 0.65)
wS = 1 − wD
F  = wS × S' + wD × D
```

| 視窗 | wS（房間本身） | wD（當下遠近） |
|---|---|---|
| 20 分鐘課間 | 0.35 | 0.65 |
| 60 分鐘 | 0.475 | 0.525 |
| 120 分鐘及以上 | 0.60 | 0.40 |

短視窗先解決來不來得及。長視窗才開始挑剔房間。

**排序。** 按 `F` 降序，相同則比 `S'`，再相同按房間編號升序。同樣的輸入永遠給出同樣的輸出，出現分歧就去查畫像或快照。

### 流程

```
function pickStudyRoom(W, p, n, u, rooms, snapshot):
    table = ensureTable(u.prefHash, snapshot.roomVersion)
    cands = []
    for r in rooms:
        if not passesFilters(r, W, p, n, u, snapshot): continue
        row   = table.rows[r.id]
        S2    = row.base * pow(1 - 0.12, effReject(row, now))
        total = walk(p, r) + walk(r, n)          # 缺一邊按 0
        k     = clamp(0.15 * len(W), 3, 12)
        T     = exp(-total / k)
        C     = min(contiguousFree(r, W.t0) / 120, 1)
        D     = 0.65*T + 0.35*C
        wD    = clamp(0.40 + 0.25*(1 - len(W)/120), 0.40, 0.65)
        F     = (1-wD)*S2 + wD*D
        cands.push({r, F, S2, T, C, D})

    sort cands by F desc, S2 desc, id asc
    return cands[0], cands[1..3]
```

每個視窗 `O(|R|)`，也就是把候選集過一遍。一天 8 個視窗、200 間房，約 1600 次評估，手機端落在毫秒預算之內。

## 算例

視窗 11:00 到 12:00，於是 `κ = 9`。前一節 10:45 在 KB 223 下課，後一節 14:00 在 CPD，只用來判斷走不走得到。

| 房間 | S | 有效拒絕 | S' | total | T | C | D | F |
|---|---|---|---|---|---|---|---|---|
| KB 227 | 0.58 | 2.0 | 0.45 | 7 分鐘 | 0.46 | 0.50 | 0.47 | 0.46 |
| LIB 3F | 0.82 | 0 | 0.82 | 21 分鐘 | 0.10 | 0.67 | 0.30 | **0.55** |
| RHT 302 | 0.69 | 0 | 0.69 | 14 分鐘 | 0.21 | 0.50 | 0.31 | 0.49 |

LIB 3F 房間最好，拿到第一，代價是走 21 分鐘。KB 227 就在樓下，身上壓著兩次拒絕，房間本身也一般，排在第二。

這個結果是一次取捨，取房間還是取走路。視窗夠長，好房間贏過近房間。把視窗縮到 20 分鐘，`wD` 升到 0.65，`κ` 掉到 3，KB 227 就翻上來。同一批房間、同一個人、兩個視窗、兩個答案。權重的存在就是為了做出這個區別。

## 引數

| 引數 | 預設 | 範圍 | 作用 |
|---|---|---|---|
| 拒絕折扣 | 每次 0.88 | 0.82 到 0.94 | 被拒一次永久降多少 |
| 拒絕半衰 | 21 天 | 7 到 60 | 舊拒絕多久淡掉 |
| `κ` 係數 | 0.15 × 視窗分鐘 | 3 到 12 | 時間懲罰的陡峭程度 |
| `C` 滿分段 | 120 分鐘 | 60 到 180 | 多長算坐得下去 |
| `wD` 區間 | 0.40 到 0.65 | 由視窗決定 | 遠近與房間本身的相對分量 |
| 熟悉度封頂 | 10 次 | 5 到 20 | 防止只去老地方 |

每一行都是「一個引數 + 一個計數器」的形態。滿三次觀測才替換預設值，使用者手動改過就清零，學習重新開始。

## 失效場景

**老地方鎖死。** 熟悉度封頂 10 次，權重 0.20，習慣最多把一間房抬起來 0.2。位置與安靜壓得過它。

**拒絕把房間打死。** 乘法結果留在零以上，八次有效拒絕後仍留 36%。翻新過的房間還能回到備選。

**視窗太短填不下。** 視窗小於 25 分鐘就不排自習。規劃器把它並進相鄰視窗，或者跳過。

**快照過期。** `contiguousFree` 讀的是快照，快照自帶抓取時間。超過十分鐘未重新整理，`C` 置 0.5，卡片標「未核實」。

**空調與採光資料缺失。** 缺失按 0.5 中性分算。這樣新房間不會背上系統性的壓分。

## 與計劃層的關係

評分只回答一個問題，這個視窗放哪間房。視窗放什麼、放多久、幾點該走，由計劃層決定。換房不動時間，改時間不動房，兩個動作各自帶著自己的撤銷記錄。

固態表屬於房間本身。[`adr/0005`](adr/0005-room-attributes-are-scored-on-the-server.zh-CN.md) 把這張表讀的六個屬性放在服務端，客戶端按修訂號快取。
