# 自习室评分

[English](room-scoring.md) · **简体中文** · [繁體中文](room-scoring.zh-TW.md)

一天里的一个空档怎么选出一间房。问题故意问得很窄：两节课之间那段时间，哪一间值得走这一趟。

各节按计算的先后排。第 0 步建一张常驻设备的表。第 1 步拿掉根本服务不了这个空档的房间。第 2 步给两个随小时变化的事实打分。第 3 步把两个分数按窗口长度加权合成。第 4 步取第一名，另留三间给「换一个」用。

本文有两部分处于不同状态。静态分已经实现，读服务端的评价表。拒绝模型、动态分与融合是设计，有取值，没有上线代码。

## 01 流程

```
第 0 步  静态表 S        一间房一行，偏好变化或拒绝时才写
第 1 步  硬过滤          整段空闲、能进、非刚离开、走得到
第 2 步  动态分 D        走过去多久、能坐多久
第 3 步  融合 F          权重随窗口长度滑动
第 4 步  取第一          选中的一间，另留三间给「换一个」
```

每一步要么缩小候选集，要么加一个数。管道里没有哪一步读第二次时钟，所以同样的输入重跑一遍还是同一间房。

**输入。**

| 记号 | 输入 | 内容 |
|---|---|---|
| `R` | 候选集 | 全部自习室，约 200 间，常驻设备 |
| `W` | 窗口 | `t0` 与 `t1`，单位分钟 |
| `p` | 前一锚点 | 结束时刻与楼栋，前面没有课则为空 |
| `n` | 后一锚点 | 开始时刻与楼栋，后面没有课则为空 |
| `u` | 用户画像 | 偏好、到访历史、拒绝记录 |
| 快照 | 可用性 | `W` 内每间房的空闲区间，带抓取时间 |

**输出。** 一间选中的房，接下来三间各带一条理由，以及每个候选的分项得分。卡片文案和调试视图读的是同一份分项得分。

## 02 静态分 S

七个因子，每一个都站在「一个人走进一间房坐下来」的角度。权重合计 1.00。

| 因子 | 它回答什么 | 权重 |
|---|---|---|
| 熟悉度 | 这栋楼我来过没有，来过几次 | 0.20 |
| 安静程度 | 坐进去吵不吵 | 0.20 |
| 桌面与座位 | 电脑和书摊不摊得开 | 0.15 |
| 插座 | 座位边有没有电 | 0.15 |
| 空调 | 香港的夏天在这种屋里能不能过 | 0.10 |
| 空间大小 | 40 到 80 座最舒服，两头都不对 | 0.10 |
| 采光 | 有没有外窗，白天开不开灯 | 0.10 |

```
S = Σ w_i × f_i
```

熟悉度与常去楼栋是同一件事，所以只占一个权重。到访次数封顶十次，一栋楼吃不下全部分数。

**三个因子不进表。** 用途匹配由安静程度回答，找自习室的人要的就是一个安静的位置。容量并进空间大小，40 到 80 座给满分。楼层并进行程时间，换一层楼就是多等一次电梯。

### 六个可评价因子怎么量化

学生写评价时给其中六个因子打 1 到 10 的整数。服务端把每个因子单独存一列，评分不从正文里解析。

```
f_i = 该因子评价均值 / 10        缺项时按剩余权重归一
```

评价里的总分只用于展示，不进排序。一个数字说不出是哪一项动了。熟悉度在服务端被去掉，因为它属于某一个账号，共用接口没有账号可读。

六个权重重新归一到 0.80，`GET /api/rooms/overview` 报的就是这个结果：

| 因子 | 表内权重 | 归一后 |
|---|---|---|
| 安静程度 | 0.20 | 0.25 |
| 桌面与座位 | 0.15 | 0.1875 |
| 插座 | 0.15 | 0.1875 |
| 空调 | 0.10 | 0.125 |
| 空间大小 | 0.10 | 0.125 |
| 采光 | 0.10 | 0.125 |

接口按十分制报结果，也就是 `S` 乘十。没有评价的房间报空分，界面打一条横线。当成零分会把它压进一个它本来没进的榜。

### 表常驻在设备上

200 行，二十多 KB，存在 IndexedDB，按偏好哈希与房间修订号做键。只有三个事件会写它。

- 偏好变化：全表重算 `base`，`n_eff` 原封不动，一次 `O(200)`。
- 拒绝发生：只写那一行。`n_eff += w_kind`，`nat = now`。
- 房间属性更新：只重算变动的那批。

```js
staticTable = {
  prefHash: "9f2c…",
  roomVersion: 14,
  rows: {
    kb227: { base: 0.58, visits: 7, n_eff: 1.8, nat: 1793 },
    lib3f: { base: 0.82, visits: 3, n_eff: 0.0, nat: 0 }
  }
}
```

衰减懒计算。读取时算 `n_eff_now = n_eff × e^(−(now − nat) / 21 天)`。落盘时顺手把值写回。后台不跑计时器。

已发布的计划留着它已经选定的房间。表立刻更新。计划在下一个揭开时刻才读新值，守住 [`algorithm.zh-CN.md`](algorithm.zh-CN.md) 里「发布之后只读」那条规则。

## 03 拒绝

拒绝不进因子表，它是挂在静态分上的长期折扣。折扣在读取分数时生效。

```
n_eff = Σ_j exp(−Δt_j / 21 天)        每次拒绝计一次，21 天衰到 37%
S'    = S × (1 − 0.12)^n_eff          每次有效拒绝乘 0.88
```

| 有效拒绝次数 | 剩余比例 |
|---|---|
| 1 | 88% |
| 2 | 77% |
| 3 | 68% |
| 5 | 52% |
| 8 | 36% |

乘法给出三个性质，每一个都用得上。每拒一次，分数降一点，这正是这个动作的意思。拒得多了房间会沉下去，同时留在零以上，翻新过的房间还能回来。撤销一次，分数回来一档，改主意不必清空历史。

点「不喜欢」记 1.0 次，换到别的房间记 0.5 次。到了又很快离开记 0.3 次。三十天内的重复拒绝自然叠加，不需要额外的加成系数。

## 04 动态分 D

两个因子，权重合计 1.00，都读窗口和两个锚点。

### 行程时间

`t_prev` 是前一站走到房间的时间，`t_next` 是房间走到后一站的时间。缺一边按 0 计。

```
slack = W.t0 − p.end − 2 分钟          缓冲从头上扣
total = t_prev + t_next
κ     = clamp(0.6 × slack, 3, 12)
T     = exp(−total / κ)
```

slack 决定一分钟走路值多少。只剩五分钟的学生 `κ` 是 3，走三分钟就掉到 0.37。有四十多分钟余量时 `κ` 到 12，走五分钟还有 0.66。时间余量就藏在这个因子里，表里没有单独的一项。

两道判断管可行性，都在算分之前。到得了，并且剩下至少五分钟能坐，即 `t_prev ≤ 窗口分钟 − 5`。走到下节课也来得及，即 `t_next ≤ 后课开始 − t1 − 2`。任意一道不过，候选直接出局。

### 连续可用

```
horizon = 从 t0 起连续空闲的分钟数
C       = min(horizon / 120, 1)
```

连续空 120 分钟得 1.0，半小时得 0.25。相邻窗口落在同一间房加 0.1，封顶 1.0。

```
D = 0.65·T + 0.35·C
```

走路占大头，因为它是学生此刻真金白银付出的那笔成本。连续可用决定这一次坐下来值不值。

## 05 融合

```
wD = clamp(0.40 + 0.25 × (1 − 窗口分钟 / 120), 0.40, 0.65)
wS = 1 − wD
F  = wS × S' + wD × D
```

| 窗口 | wS（房间本身） | wD（当下远近） | 读法 |
|---|---|---|---|
| 20 分钟课间 | 0.35 | 0.65 | 先解决来不来得及 |
| 60 分钟 | 0.475 | 0.525 | 远近与舒适各半 |
| 120 分钟及以上 | 0.60 | 0.40 | 开始挑剔房间 |

**排序。** 按 `F` 降序，相同则比 `S'`，再相同按房间编号升序。同样的输入永远给出同样的输出，出现分歧就去查画像或快照。

```js
function pickStudyRoom(W, p, n, u, rooms, snapshot) {
  const table = ensureTable(u.prefHash, snapshot.roomVersion)
  const cands = []
  for (const r of rooms) {
    if (!passesFilters(r, W, p, n, u, snapshot)) continue
    const row = table.rows[r.id]
    const S2 = row.base * Math.pow(1 - 0.12, effReject(row, now))
    const total = walk(p, r) + walk(r, n)              // 缺一边按 0
    const k = clamp(0.6 * slack(W, p), 3, 12)
    const T = Math.exp(-total / k)
    const C = Math.min(contiguousFree(r, W.t0) / 120, 1)
    const D = 0.65 * T + 0.35 * C
    const wD = clamp(0.40 + 0.25 * (1 - len(W) / 120), 0.40, 0.65)
    cands.push({ r, F: (1 - wD) * S2 + wD * D, S2, T, C, D })
  }
  cands.sort((a, b) => b.F - a.F || b.S2 - a.S2 || a.r.id - b.r.id)
  return { pick: cands[0], swaps: cands.slice(1, 4) }
}
```

每个窗口 `O(|R|)`，把候选集过一遍。一天 8 个窗口、200 间房，约 1600 次评估，手机端落在毫秒预算之内。

## 06 算例

窗口 11:00 到 12:00。前一节 10:45 在 KB 223 下课，所以 slack 是 13 分钟，`κ` 是 7.8。后一节 14:00 在 CPD，只用来判断走不走得到。窗口 60 分钟，所以 `wS` 是 0.475，`wD` 是 0.525。

| 房间 | S | 有效拒绝 | S' | 步行 | T | C | D | F |
|---|---|---|---|---|---|---|---|---|
| KB 227 | 0.58 | 2.0 | 0.45 | 7 分钟 | 0.41 | 0.50 | 0.44 | 0.45 |
| LIB 3F | 0.82 | 0 | 0.82 | 21 分钟 | 0.07 | 0.67 | 0.28 | **0.54** |
| RHT 302 | 0.69 | 0 | 0.69 | 14 分钟 | 0.17 | 0.50 | 0.29 | 0.48 |

LIB 3F 房间最好，拿到第一，代价是走 21 分钟。KB 227 就在楼下，身上压着两次拒绝，房间本身也一般，排在第三。

这个结果是一次取舍，取房间还是取走路。窗口缩到 20 分钟，`wD` 升到 0.65，slack 变小所以 `κ` 掉到 3，KB 227 就翻上来。同一批房间、同一个人、两个窗口、两个答案。权重的存在就是为了做出这个区别。

## 07 参数

| 参数 | 默认 | 范围 | 作用 |
|---|---|---|---|
| 拒绝折扣 | 每次 0.88 | 0.82 到 0.94 | 被拒一次降多少 |
| 拒绝半衰 | 21 天 | 7 到 60 | 旧拒绝多久淡掉 |
| `κ` 系数 | 0.6 × slack | 夹在 3 与 12 | 时间惩罚的陡峭程度 |
| `C` 满分段 | 120 分钟 | 60 到 180 | 多长算坐得下去 |
| `wD` 区间 | 0.40 到 0.65 | 由窗口决定 | 远近与房间本身的相对分量 |
| 熟悉度封顶 | 10 次 | 5 到 20 | 防止只去老地方 |
| 观测门限 | 3 次评分 | 3 到 10 | 满几次才用评价均值替换默认值 |

每一行都是「一个参数 + 一个计数器」的形态。满三次观测才替换默认值，用户手动改过就清零，学习重新开始。

这些参数是设计值，背后没有实测。demo 里把 `S'`、`T`、`C`、`D`、`F` 都打印出来，排序可以手算核对。

## 失效场景

**老地方锁死。** 熟悉度封顶 10 次，权重 0.20，习惯最多把一间房抬起来 0.2。位置与安静压得过它。

**拒绝把房间打死。** 乘法结果留在零以上，八次有效拒绝后仍留 36%。翻新过的房间还能回到备选。

**窗口太短填不下。** 窗口小于 25 分钟就不排自习。规划器把它并进相邻窗口，或者跳过。

**快照过期。** `contiguousFree` 读的是快照，快照自带抓取时间。超过十分钟未刷新，`C` 减半，卡片标「未核实」。

**某个因子没有数据。** 没有数据的因子不进计算，它的权重摊给其余项。一间房完全没有评价就报空分，界面打横线。

## 与计划层的关系

评分只回答一个问题，这个窗口放哪间房。窗口放什么、放多久、几点该走，由计划层决定。换房不动时间，改时间不动房，两个动作各自带着自己的撤销记录。

静态表属于房间本身。[`adr/0005`](adr/0005-room-attributes-are-scored-on-the-server.zh-CN.md) 把这张表读的六个属性放在服务端，客户端按修订号缓存。
