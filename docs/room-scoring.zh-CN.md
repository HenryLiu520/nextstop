# 自习室评分

[English](room-scoring.md) · **简体中文** · [繁體中文](room-scoring.zh-TW.md)

一天里的一个窗口怎么选出房间。这是一份设计文档。原型里的规划器仍然是桩，所以下面每个数字都是设计值，或者来自算例。

## 引言

评分只回答一个问题，这个窗口、这名学生，选哪一间房。窗口放什么、放多久，由计划层决定。评分读三样东西：窗口本身，从前一站走到房间的时间，从房间走到后一站的时间。

**输入。**

| 符号 | 输入 | 内容 |
|---|---|---|
| `R` | 候选集 | 全部自习室，约 200 间，存在设备上 |
| `W` | 窗口 | `t0` 与 `t1`，单位分钟 |
| `p` | 前一个锚点 | 结束时刻与楼栋，前面没有课则为空 |
| `n` | 后一个锚点 | 开始时刻与楼栋，后面没有课则为空 |
| `u` | 用户画像 | 偏好、到访历史、拒绝记录 |
| 快照 | 可用性 | `W` 内每间房的空闲区间，带抓取时间戳 |

**输出。** 一间选中的房，接下来三间各带一条理由，以及每个候选的分项得分。卡片文案和调试视图都读这份分项得分。

### 硬过滤

四个判断跑在任何分数之前，过滤就到这里为止。

```
free(r, W)        整段空闲
allowed(u, r)     这个身份能进
r != last_room    不是刚离开的那间
reachable(r, W)   走得过去，判据见「行程时间」
```

座位数不进过滤，一个学生总能在楼里找到位置。真正的问题是这间房值不值得走一趟。

## 固态表

七个因子，每一个都站在「一个人走进一间房坐下来」的角度。权重合计 1.00。

| 因子 | 衡量什么 | 打分方式 | 权重 |
|---|---|---|---|
| 熟悉度 | 这名学生反复回去的那栋楼、那几间房 | `min(该楼到访次数 / 10, 1)` | 0.20 |
| 安静程度 | 这间房本身有多吵 | 静音区 1.0，普通 0.65，讨论区 0.35，再按实时占用率下调 | 0.20 |
| 桌面与座位 | 电脑和书能不能并排摊开 | 桌面宽 90cm 及以上得 1，尺寸每小一档就往下减 | 0.15 |
| 插座 | 座位边有没有电 | 每座都有 1.0，沿墙有 0.5，没有 0 | 0.15 |
| 空调 | 香港的夏天 | 有 1.0，没有 0 | 0.10 |
| 空间大小 | 太挤难受，太空也不安 | 40 到 80 座满分，两端各减半 | 0.10 |
| 采光 | 有窗，白天不用开灯 | 外窗 1.0，天井窗 0.5，无窗 0 | 0.10 |

```
S = Σ_i w_i × f_i
```

熟悉度与常去楼栋是同一件事，合并成一项。到访次数封顶 10 次，一栋楼吃不下全部分数。

### 表外的三个因子

**用途匹配。** 找自习室的学生要的是一个安静的位置。安静因子已经把这个问题答了。

**容量贴合。** 一个人不会去数房间的座位够不够。容量作为宽敞度的代理，出现在空间大小里。

**楼层偏好。** 楼层真正影响的是等电梯的时间，等电梯就是走路。行程时间比单独一个偏好算得更准。

### 表常驻在设备上

200 行，二十多 KB，存在 IndexedDB，按偏好哈希与房间修订号做键。只有三个事件会写它。

- 偏好变化：全表重算 `base`，`n_eff` 原封不动，一次 `O(200)`。
- 拒绝发生：只写那一行。`n_eff += w_kind`，`nat = now`。
- 房间属性更新：只重算变动的那批。

```js
staticTable = {
  prefHash: "9f2c…",
  roomVersion: 14,
  rows: {
    kb227: { base: 0.58, visits: 7, n_eff: 1.8, nat: 1793 },
    lib3f: { base: 0.82, visits: 3, n_eff: 0.0, nat: 0 }
  }
}
```

衰减懒计算。读取时算 `n_eff_now = n_eff × e^(−(now − nat) / 21 天)`。落盘时顺手把值写回。后台不跑计时器。

已发布的计划留着它已经选定的房间。表立刻更新。计划在下一个揭开时刻才读新值，守住 [`algorithm.zh-CN.md`](algorithm.zh-CN.md) 里「发布之后只读」那条规则。

## 拒绝

拒绝不进因子表，它是挂在固态分上的长期折扣。折扣在读取分数时生效。

```
n_eff = Σ_j exp(−Δt_j / 21 天)        每次拒绝计一次，21 天衰到 37%
S'    = S × (1 − 0.12)^n_eff          每次有效拒绝乘 0.88
```

| 有效拒绝次数 | 剩余比例 |
|---|---|
| 1 | 88% |
| 2 | 77% |
| 3 | 68% |
| 5 | 52% |
| 8 | 36% |

乘法给出三个性质，每一个都用得上。每拒一次，分数降一点，这正是这个动作的意思。拒得多了房间会沉下去，同时留在零以上，翻新过的房间还能回来。撤销一次，分数回来一档，改主意不必清空历史。

点「不喜欢」记 1.0 次，换到别的房间记 0.5 次。到了又很快离开记 0.3 次。三十天内的重复拒绝自然叠加，不需要额外的加成系数。

## 动态分

两个因子，权重合计 1.00，都读窗口和两个锚点。

### 行程时间

`t_prev` 是前一站走到房间的时间，`t_next` 是房间走到后一站的时间。缺一边按 0 计。

```
total = t_prev + t_next
slack = t0 − 前一个锚点结束时刻 − 2 分钟缓冲
κ     = clamp(0.6 × slack, 3, 12)
T     = exp(−total / κ)
```

slack 决定一分钟走路的价格。slack 只有 5 分钟时，`κ = 3`，走 3 分钟掉到 0.37。slack 有 40 分钟时，`κ = 12`，走 5 分钟仍是 0.66。

时间余量就藏在这个因子里。缓冲越少，同样的距离扣得越狠，再单列一个余量因子只是把同一件事写两遍。

后面那节课只用来看走不走得到，判据是 `t_next ≤ next_start − t1 − 2`。过不了这个判断的候选直接出局。

### 连续可用

```
horizon = 从 t0 起连续空闲的分钟数
C       = min(horizon / 120, 1)
```

连续空 120 分钟得 1.0，半小时得 0.25。相邻窗口落在同一间房加 0.1，封顶 1.0。

```
D = 0.65·T + 0.35·C
```

走路占大头，因为它是学生此刻真金白银付出的那笔成本。连续可用决定这一次坐下来值不值。

## 融合

```
wD = clamp(0.40 + 0.25 × (1 − 窗口分钟 / 120), 0.40, 0.65)
wS = 1 − wD
F  = wS × S' + wD × D
```

| 窗口 | wS（房间本身） | wD（当下远近） |
|---|---|---|
| 20 分钟课间 | 0.35 | 0.65 |
| 60 分钟 | 0.475 | 0.525 |
| 120 分钟及以上 | 0.60 | 0.40 |

短窗口先解决来不来得及。长窗口才开始挑剔房间。

**排序。** 按 `F` 降序，相同则比 `S'`，再相同按房间编号升序。同样的输入永远给出同样的输出，出现分歧就去查画像或快照。

### 流程

```
function pickStudyRoom(W, p, n, u, rooms, snapshot):
    table = ensureTable(u.prefHash, snapshot.roomVersion)
    cands = []
    for r in rooms:
        if not passesFilters(r, W, p, n, u, snapshot): continue
        row   = table.rows[r.id]
        S2    = row.base * pow(1 - 0.12, effReject(row, now))
        total = walk(p, r) + walk(r, n)          # 缺一边按 0
        k     = clamp(0.6 * slack(W, p), 3, 12)
        T     = exp(-total / k)
        C     = min(contiguousFree(r, W.t0) / 120, 1)
        D     = 0.65*T + 0.35*C
        wD    = clamp(0.40 + 0.25*(1 - len(W)/120), 0.40, 0.65)
        F     = (1-wD)*S2 + wD*D
        cands.push({r, F, S2, T, C, D})

    sort cands by F desc, S2 desc, id asc
    return cands[0], cands[1..3]
```

每个窗口 `O(|R|)`，也就是把候选集过一遍。一天 8 个窗口、200 间房，约 1600 次评估，手机端落在毫秒预算之内。

## 算例

窗口 11:00 到 12:00，前一节 10:45 在 KB 223 下课。于是 `slack = 13`，`κ = 7.8`。后一节 14:00 在 CPD，只用来判断走不走得到。

| 房间 | S | 有效拒绝 | S' | total | T | C | D | F |
|---|---|---|---|---|---|---|---|---|
| KB 227 | 0.58 | 2.0 | 0.45 | 7 分钟 | 0.41 | 0.50 | 0.44 | 0.46 |
| LIB 3F | 0.82 | 0 | 0.82 | 21 分钟 | 0.07 | 0.67 | 0.28 | **0.54** |
| RHT 302 | 0.69 | 0 | 0.69 | 14 分钟 | 0.17 | 0.50 | 0.29 | 0.48 |

LIB 3F 房间最好，拿到第一，代价是走 21 分钟。KB 227 就在楼下，身上压着两次拒绝，房间本身也一般，排在第二。

这个结果是一次取舍，取房间还是取走路。窗口够长，好房间赢过近房间。把窗口缩到 20 分钟，`wD` 升到 0.65，`κ` 掉到 3，KB 227 就翻上来。同一批房间、同一个人、两个窗口、两个答案。权重的存在就是为了做出这个区别。

## 参数

| 参数 | 默认 | 范围 | 作用 |
|---|---|---|---|
| 拒绝折扣 | 每次 0.88 | 0.82 到 0.94 | 被拒一次永久降多少 |
| 拒绝半衰 | 21 天 | 7 到 60 | 旧拒绝多久淡掉 |
| `κ` 系数 | 0.6 × slack | 3 到 12 | 时间惩罚的陡峭程度 |
| `C` 满分段 | 120 分钟 | 60 到 180 | 多长算坐得下去 |
| `wD` 区间 | 0.40 到 0.65 | 由窗口决定 | 远近与房间本身的相对分量 |
| 熟悉度封顶 | 10 次 | 5 到 20 | 防止只去老地方 |

每一行都是「一个参数 + 一个计数器」的形态。满三次观测才替换默认值，用户手动改过就清零，学习重新开始。

## 失效场景

**老地方锁死。** 熟悉度封顶 10 次，权重 0.20，习惯最多把一间房抬起来 0.2。位置与安静压得过它。

**拒绝把房间打死。** 乘法结果留在零以上，八次有效拒绝后仍留 36%。翻新过的房间还能回到备选。

**窗口太短填不下。** 窗口小于 25 分钟就不排自习。规划器把它并进相邻窗口，或者跳过。

**快照过期。** `contiguousFree` 读的是快照，快照自带抓取时间。超过十分钟未刷新，`C` 置 0.5，卡片标「未核实」。

**空调与采光数据缺失。** 缺失按 0.5 中性分算。这样新房间不会背上系统性的压分。

## 与计划层的关系

评分只回答一个问题，这个窗口放哪间房。窗口放什么、放多久、几点该走，由计划层决定。换房不动时间，改时间不动房，两个动作各自带着自己的撤销记录。

固态表属于房间本身。[`adr/0005`](adr/0005-room-attributes-are-scored-on-the-server.zh-CN.md) 把这张表读的六个属性放在服务端，客户端按修订号缓存。
