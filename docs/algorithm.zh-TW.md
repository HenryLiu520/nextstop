# NextStop：規劃與修復演算法

[English](algorithm.md) · [簡體中文](algorithm.zh-CN.md) · **繁體中文**

一天如何從固定課表規劃出來，以及現實發生偏移時那份計劃如何被修復。這是一份設計文件。原型裡的 planner 只是一個 stub（第 9 節），所以這裡沒有任何實測結論。它要支撐的主張只有一句話：出現偏離時，系統改動儘可能少的站點，並且比一次完整重算改得更少。

## 1. 問題陳述

**輸入。**

| 符號 | 輸入 | 內容 |
|---|---|---|
| `A` | anchors | 固定安排，含樓、房間、開始、結束 |
| `G` | gaps | 由 `A` 推匯出的空閒區間 |
| `W` | walk matrix | 樓對之間的分鐘數，按學習到的步行係數縮放 |
| `R` | availability | `free(room, t0, t1)`，來自已有的 availability engine |
| `P` | profile | 引數：時間容差、樓容差、buffer、步行係數、用餐視窗 |
| `L` | location | 一次定位讀取，僅在 reveal 時 |
| `D` | deviation | `delay(min)`、`change(stop)`、`skip(anchor)`、`arrive(stop)` |

**輸出。** 首個 anchor 與末個 anchor 之間的有序站點序列。一個站點是 `(type, purpose, building, room, start, end)`，type 取四種之一：`study`、`eat`、`meet`、`transit`。
樓與樓之間的步行是一個 `transit` 站點，同一棟樓內部的步行不構成站點。沒有 `wait` 型別：每個算出的 gap 要麼被填滿，要麼併入相鄰站點。

**約束。**

1. anchor 是權威的。planner 從不移動、縮短或質疑它。
2. 兩個站點不重疊，且某個 anchor 之前的最後一個站點結束得足夠早，能走過去。
3. 樓與樓之間的移動永遠要付出代價，要麼作為一個 `transit` 站點，要麼算在 gap 之內。
4. 只有當 `free(room, t0, t1)` 在整個區間成立時，站點才佔用該房間。
5. `arrive(t)` 是終局。過去的站點被截斷，絕不重新規劃。
6. 出勤變更屬於學生。planner 從不產生這種變更。
7. 已提交的計劃是每一次比較的基準（第 3 節）。

**成功標準。** 四個數字，都可測，都還沒測。

| 指標 | 定義 | 方向 | 狀態 |
|---|---|---|---|
| 操作次數 | 跟隨一天所需的手勢數 | 不增加 | 未插樁 |
| 執行率 | 未經使用者替換即到達開始時間的計劃站點佔比 | 越高越好 | 未插樁 |
| 每次修復改動的站點數 | 每次偏離中 `(purpose, building, start)` 發生移動的站點數 | 1 到 2，低於完整重算 | 未插樁 |
| 相對完整重算的差值 | 同一偏離下改動的站點數與未受影響的執行率 | 修復必須勝出 | 開關已定義，未實現 |

第四個是承重的那個。它不是延遲數字，是穩定性數字：最小修復是否比重新求解全部留下更多的原樣。同一次偏離必須能在兩條路徑上重放，否則這個比較毫無意義。

## 2. 四個層

```
+--------------------------------------------------------------------+
| L1  ANCHORS    fixed, authoritative, never questioned              |
|      09:00 COMP1100 CSIT   11:00 MATH1013 KB   13:00 COMP2100 CSIT |
+--------------------------------------------------------------------+
                     | gaps between commitments
                     v
+--------------------------------------------------------------------+
| L2  FREE TIME  gap = next_start - prev_end - walk - buffer         |
|                usable if >= min_stop, else merged, never a wait    |
+--------------------------------------------------------------------+
                     | usable intervals
                     v
+--------------------------------------------------------------------+
| L3  FILL       one stop per interval: study / eat / meet           |
|                transit between buildings, no wait type             |
+--------------------------------------------------------------------+
                     | a deviation is observed
                     v
+--------------------------------------------------------------------+
| L4  REPAIR     keep what still holds, re-solve the broken window,  |
|                then check the neighbouring stop                    |
+--------------------------------------------------------------------+
```

**L1 Anchors。** 課表讀一次，併為這一天凍結。它不是偏好，也不是 planner 可以糾正的東西。即使學生遲到，anchor 仍然按它自己的時間開始：變化的是學生的可用性，不是課表。正是這種不可變性讓其餘部分可處理，因為每個視窗於是都有了兩堵固定的牆。

**L2 空閒時間。** 每個 gap 是一個 anchor 的結束到下一個 anchor 的開始之間的區間，減去走到下一棟樓的步行時間，再減去一個 buffer。餘量只有達到一個站點的最短時長（`min_stop`，預設 15 分鐘）才可用。達不到就把這個 gap 併入相鄰區間，而不是產出一個殘樁站點或一個空塊。
這一層只輸出時長，所以可以單獨測試。

**L3 填充。** 每個可用區間得到一個站點，而站點的結束時間由它後面的東西推匯出來，不是自由選擇的。型別來自目的優先順序（本來會被錯過的用餐視窗優先順序高於學習），地點來自 availability engine 加步行矩陣。填充每天在 reveal 時執行一次，之後計劃只讀，直到出現偏離。正是這一層讓輸出成為一個序列而不是一個集合：為 10:00 選定的站點決定了 11:00 時學生站在哪棟樓裡。區間裡填哪一間房由另一套過程決定，寫在 [`room-scoring.zh-TW.md`](room-scoring.zh-TW.md)。

**L4 修復。** 任何偏離從這裡進入。修復識別出哪些站點相對已提交計劃不再成立，其餘原樣保留，只在破損視窗內部重新求解，然後檢查下一個站點，確認修法沒有溢位視窗。修復是唯一可以寫入已釋出計劃的層，而且它總會寫入一條 undo 記錄。

## 3. 同一性判據

一個候選站點 `s'` 與已提交站點 `s` 是同一件事，當且僅當以下三條全部成立。

1. **目的不變。** 同一門課的學習塊，`meet` 的是同一組人，吃飯仍然是吃飯。目的是 `(type, subject_ref)`：在另一棟樓學 COMP1100 是同一個目的，換成學 COMP2100 就不是。
2. **地點是同一棟樓，或在步行容差之內。** 同一 building id，或 `walk(s'.building, s.building) <= building_tolerance`（預設 4 分鐘）。兩分鐘外的另一棟樓算同一個地點。十二分鐘外的不算。
3. **開始時間相差不超過時間容差。** `abs(s'.start - s.start) <= time_tolerance`（預設 15 分鐘）。

三條都要，不是其中任意兩條。只看目的，一天可以任意滑走。只看地點，一個學習塊可以變成一頓午飯。只看時間，學生可能最後待在另一棟樓裡，卻被告知什麼都沒變。

基準永遠是已提交的計劃，也就是學生實際看到的那個版本。拿上一版內部候選去比較會容許緩慢漂移：每次修復 14 分鐘，每次都報告無變化，到午飯時已經差了一個小時。

判據之所以存在，是因為修復需要一個停止條件。沒有同一性判斷，每一次偏離都得把下游每個站點當作可疑，修復就退化成多走幾步的重算。判據是決定修復做多少工作的閘門，所以它的兩個容差是系統裡最承重的引數。它們是引數，不是常量，第 8 節就按引數對待它們。

一個刻意的後果：已確立的站點永不重新最佳化，即使存在嚴格更好的位置。計劃不是最優的，是穩定的。一個記得「10:00，CSIT 105」的學生髮現它還在原處，得到的是更好的計劃給不了的東西。代價是永久的區域性次優，這是知情的取捨。

## 4. 修復流程

```text
repair(plan, deviation):
    observe = (t_now, building_now)                # the deviation, as reported
    W       = window(plan, observe)                # first broken stop to last broken stop
    keep    = [s for s in plan if same_thing(s, committed[s])]
    broken  = plan - keep
    if broken is empty: return plan
    for rank in [SHIFT, ROOM, BUILDING, CANCEL]:   # attendance is not a planner rank
        cand = solve(W, keep, rank)
        if feasible(cand): break
    cand = expand_until_stable(W, cand)            # at most 2 expansions
    return commit(cand, undo_log)
```

1. 兩個值進，一份計劃出。這次呼叫可重放，第 1 節的比較之所以可能，全靠這一點。
2. `observe` 把事件歸一成一個時間和一棟樓。20 分鐘的超時和一次「我遲到了」的點選產生同一個觀察，所以修復只有一個入口。
3. `W` 是破損視窗：從第一個再也站不住的站點，到觀察使其失效的最後一個站點。anchor 是視窗的牆，從不是視窗的成員。
4. `keep` 對每個站點應用第 3 節的三條測試，基準是已提交版本。
5. `broken` 是補集。在典型的偏離裡它有一到兩個成員。
6. 沒有破損站點，說明計劃仍然成立，於是什麼都不寫。這一情形很便宜。
7. 第 5 節的階梯按順序走。每一級是一次獨立的求解，第一個可行的級別勝出，走查到此為止。
8. `solve` 只在 `W` 之內列舉候選位置。它從來看不到一天的其餘部分，這正是它成本受限的原因。
9. 接受某一級之前先測可行性。不可行的候選被丟棄，接著試下一級。
10. 鄰居檢查只問一個問題：`W` 的新邊界是否把下一個保留站點推過時間容差，或破壞走到它的那段步行。級聯在接縫處被抓到。
11. 如果會，視窗擴大一個站點並重新求解，最多兩次。之後呼叫方回退到對剩餘一天的完整重規劃，這是誠實且少見的。
12. `commit` 釋出計劃並追加一條 undo 記錄。一次糟糕的修復只花一次點選，不花一天。

## 5. 成本順序

修復爬這道階梯，停在第一個能給出可行視窗的級別。順序是字典序，不是加權和。加權和會讓三個便宜動作壓過一個昂貴動作，而學生體驗到的是那個昂貴動作。

| 級別 | 動作 | 學生注意到什麼 | 誰可以觸發 | 可撤銷 |
|---|---|---|---|---|
| 1 | 把邊界平移 5 到 10 分鐘 | 同一個站點，同一個房間，分鐘挪了 | system | 是 |
| 2 | 換房間，同一棟樓 | 同一棟樓同一時間，房間號不同 | system | 是 |
| 3 | 換樓 | 另一棟樓，步行更久 | system | 是 |
| 4 | 取消整個站點 | 一個站點消失，它的時間被併入 | system | 是 |
| 5 | 改出勤 | 這門課被視為空閒，僅對該學生 | user only | 是 |

由偏離本身強制的平移不算在 planner 頭上。如果學生遲了 20 分鐘，站點的開始時間移動是因為學生移動了，不是 planner 選擇要移。階梯給 planner 在現實之上額外新增的東西定價。這也是級別 1 封頂 10 分鐘的原因：更大的平移意味著這個站點正在被重新推導，那屬於視窗求解。

級別 4 是取消，不是等待。騰出來的區間不會變成一個空塊，它被併入相鄰站點或併入步行。一個被取消的站點如果留下可見的死時間，那是違反第 1 節約束 3 的 bug。

級別 5 永不由 planner 進入。出勤是隻有學生能主張的事實。系統會圍繞一次缺課來規劃，但永遠不會決定一次缺課。

## 6. 複雜度

`n` 是一天的站點數（實踐中 4 到 8）。`m` 是每個站點的候選地點數（幾十到低三位數）。`k` 是破損站點數（典型 1 到 2）。`w` 是破損視窗內的站點數（典型 2 到 4）。

| 例程 | 成本 | 何時執行 |
|---|---|---|
| 完整規劃 | `O(n * m)` | reveal 時，每天一次 |
| 修復 | `O(k * m * w)` | 每次偏離 |
| 鄰居檢查 | `O(1)` | 每次修復之後 |
| 最壞情況修復 | `O(n * m)` | 偏離發生在當天第一個站點時 |

誠實的比較。完整重算是 `O(n * m)`。修復是 `O(k * m * w)`，比它好 `n / (k * w)` 倍。取 `n = 6`、`k = 1`、`w = 3`，這個倍數是 2。偏離發生得早時，視窗覆蓋剩餘一天的大部分，倍數趨近 1。最壞情況下沒有漸近優勢，本文件也不主張有。

絕對數字兩邊都很小。六個站點對上百個候選房間，是幾百次可行性檢查，每次都由一個預計算的區間索引回答。沒人會注意到那幾毫秒。最小修復的理由不是速度，是改動的站點數。完整重算可能重新排序每個房間、重新推導每個時長，於是它的輸出在本來沒問題的地方也不同，每一處不同都要學生重讀自己的一天。

## 7. 一個算例

示例說明，不是實測結果。數字是為了能走通而選的，能產出它們的 planner 就是第 9 節描述的 stub。

anchor：09:00 到 10:00 COMP1100 在 CSIT，11:00 到 12:00 MATH1013 在 KB，13:00 到 14:00 COMP2100 在 CSIT，16:00 到 17:00 PHYS1200 在 CSIT。CSIT 到 KB 步行 7 分鐘，buffer 為 3。

| # | 型別 | 地點 | 已提交 | 修復後 |
|---|---|---|---|---|
| S1 | study | CSIT 105 | 10:03 到 10:47 | 10:23 到 10:46，已改動 |
| S2 | transit | CSIT 到 KB | 10:47 到 10:56 | 10:46 到 10:53，保留 |
| S3 | eat | KB food court | 12:05 到 12:42 | 未變，保留 |
| S4 | transit | KB 到 CSIT | 12:42 到 12:51 | 未變，保留 |
| S5 | study | CSIT 227 | 14:05 到 15:50 | 未變，保留 |
| S6 | study | CSIT 227 | 17:05 到 18:20 | 未變，保留 |

10:20 時學生報告超時 20 分鐘，人仍在 CSIT。50 分鐘的可用 gap 變成 33 分鐘，而走到 KB 的那一段不能挪，因為 MATH1013 是 anchor。

同一性測試。S1 不能在 10:03 開始，因為學生到 10:20 才空閒，這已經比計劃開始晚了 17 分鐘，超出 15 分鐘容差，所以 S1 破損。
S2 保持了它的目的、它的樓對，以及一分鐘以內的開始時間，所以它被保留。S3 到 S6 位於視窗之外，被保留。

階梯在跨 S1 與 S2 的視窗內走查，左邊以 10:20 為界，右邊以 11:00 為界。級別 1 適用：同一房間裡的同一個學習站點，邊界調整，容得下 23 分鐘學習，步行與 buffer 仍然完整。級別 2 到 4 從未到達。

改動的站點：1。鄰居檢查透過，因為下一個保留站點是 anchor，走到它的步行仍然成立。

作為對照，同一次偏離的完整重算會重新推導全部四個 gap。在這個示例裡它落在三處不同：上午的學習挪到 KB 一側，午飯站點因為求解器不再看到原來的邊界而縮到更短的視窗，下午的學習換了房間因為 availability 快照被重新排序。改動的站點：3。結果紙面上並不更好，實踐中卻明顯更擾人，而第 1 節的比較正是為量這個量而設計的。

## 8. 失效模式

**過鬆的判據。** 放寬三條測試，大多數候選都能匹配，計劃就在沒人察覺中漂移。隨之有兩種形態：學生走到 CSIT 105 發現它是空的，因為那個塊在樓內悄悄挪了位置，或者一個學習塊長大吃掉了午飯，因為目的和地點都匹配，只有時長變了。對兩者的防護是，同一性以已提交計劃為基準度量，且站點保持它的型別與科目。

**過緊的判據。** 收窄容差，普通偏離就會打斷下游的一切。學生遲到 8 分鐘，整個下午被重新求解。症狀是執行率崩塌，同時每次修復改動的站點數逼近完整重算的數值，於是修復層變得毫無意義。

**容差敏感性。** 兩個容差都會牽動全部四個指標，所以它們是掃描的，不是固定死的。`time_tolerance` 取 5，一次 6 分鐘的輕推就變成破損站點。取 30，不同的站點合併成同一個身份，一天可以每個事件滑掉半小時。還有一條一致性約束：級別 1 最多平移一個站點 10 分鐘，所以 `time_tolerance` 低於 10 會讓最便宜的 planner 動作與同一性測試自相矛盾，產出報告了意外變動的修復。這一對必須滿足 `time_tolerance > max shift at rank 1`。`building_tolerance` 的單位是步行分鐘，抬高它會讓跨樓的短跳變成免費，從而悄悄廢掉同樓規則。

**級聯。** 一次修復可能把下一個站點推過容差，進而打斷再下一個。鄰居檢查抓一步，擴張迴圈抓兩步，之後剩餘的一天被完整重規劃。那個回退是對最小性主張的真實失敗，所以單獨計數並報告，而不是藏進改動站點平均值裡。迴圈會終止，因為每次擴張都嚴格增大視窗，而視窗被計劃所限。

**永久的區域性次優。** 已確立的站點永不重新最佳化，所以一個變吵或變滿的房間會留下，只要它仍算同一件事。補救辦法是使用者自己的「換掉這一個」動作，那是使用者發起的打斷，不是修復。

**陳舊的 availability。** availability 在 reveal 時讀取，之後就被信任。如果房間在 reveal 與到達之間被佔滿，計劃就是錯的，直到使用者報告。系統不做輪詢，所以這是被接受的，而不是被解決的。

**超時超過 gap。** 超過 gap 的延遲絕不能用縮短 anchor 來吸收。anchor 勝出，站點被取消，下一個 anchor 遲到加入。為了塞進一個站點而壓縮 anchor 的 planner 是違約的。

## 9. 未實現的部分

原型裡的 planner 是一個 stub。它讀 anchor，算 gap 時長，並在每個可用區間放一個時長固定的學習站點。它不查詢房間，不走成本階梯，不跑同一性測試，也沒有修復路徑。對它呼叫 `repair` 會返回你交給它的那份計劃。

已存在：anchor 攝入、gap 算術、基於課表的 availability engine、樓到樓的步行矩陣、四狀態狀態機，以及偏離事件。還不存在：視窗求解器、階梯、鄰居檢查、程式碼裡的同一性測試，以及第 1 節四個指標的插樁。

所以本文件裡的每個數字要麼是設計引數，要麼是示例，第 7 節因此自帶警告。修復比完整重算改動更少站點這一主張仍是假設。它是比較開關首先要測的東西，在任何介面工作壓到它上面之前。

同樣刻意缺席的：自動出勤變更、容差的多天學習（它們從預設值起步），以及小群組在 claim 與 retract 路徑之外的任何預訂。這些是設計的邊界，不是原型的缺口。
