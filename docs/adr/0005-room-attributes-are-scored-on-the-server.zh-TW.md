# 0005. 房間屬性在服務端打分

[English](0005-room-attributes-are-scored-on-the-server.md) · [簡體中文](0005-room-attributes-are-scored-on-the-server.zh-CN.md) · **繁體中文**

- Status: Accepted
- Date: 2026-11-11
- Scope: 房間屬性端點、評分層、`docs/room-scoring.md`

## 背景

自習室推薦要在一個窗口裡給房間排序。排序有兩部分。動態部分讀窗口、讀從上一個停靠點走過來的時間、讀走到下一個停靠點的時間。固態部分描述房間本身：有多安靜，桌面放不放得下電腦和書，座位旁邊有沒有電。

固態部分屬於房間。它落在計劃之外，也落在可用性答案之外。可用性告訴你 2A 在 10:00 到 11:00 是空的。它說不出 2A 裡有多吵，也說不出牆邊有沒有插座。同一個窗口裡空著的兩間房，差別可以是整個決定。

客戶端能讀可用性，能據此算出佔用。同一個客戶端沒有來源知道門邊是電梯廳、桌面只有 60 公分寬、窗朝天井。這些事實來自走一趟樓、一張平面圖，或者物業辦公室。

排序還需要同一把尺子。同一個窗口裡的兩位學生比較的是同樣的 200 間房。每臺手機自己打分，就得到自己的順序，一間房在一臺裝置上排第一、在另一臺上排第四，候選列表就不再是一個答案。

## 決策

後端提供房間屬性：每間房六個維度，每條是 0 到 5 的整數，裝在一份帶修訂號的文件裡。

```
GET /v1/rooms/attributes
{ "rev": 14,
  "updatedAt": "2026-11-11T09:00:00Z",
  "rooms": [ { "code": "KB227", "quiet": 4, "desk": 3, "sockets": 3,
               "ac": 5, "spaciousness": 4, "daylight": 3 } ] }
```

每個維度在 0、3、5 各有一個錨點。審計員走進房間，寫下與它相符的整數。

| 維度 | 鍵 | 0 | 3 | 5 |
|---|---|---|---|---|
| 安靜度 | `quiet` | 門朝電梯廳、食堂或人流不斷的走廊 | 開放區，旁邊一桌在說話 | 門內的靜音區，遠離人流 |
| 桌面與座位 | `desk` | 沙發或長凳，沒有書寫平面 | 共用長桌，放得下電腦和一本書 | 獨立桌面，寬 90 公分以上，配椅子 |
| 插座密度 | `sockets` | 沒有可用插座 | 沿牆有插座 | 每個座位都有插座 |
| 空調 | `ac` | 沒有空調 | 空調按樓宇時間表開關 | 房間內有控制面板的空調 |
| 空間 | `spaciousness` | 每個座位 1.0 平方米以下，桌子連排 | 每個座位約 2.0 平方米 | 每個座位 3.0 平方米以上，多數桌子旁邊有空位 |
| 採光 | `daylight` | 無窗 | 窗朝天井或內院 | 外窗，自然光照到桌面 |

1、2、4 用來記落在兩行之間的房間。審計員寫下與房間相符的整數，安靜度上的 2 表示比食堂安靜、比開放區吵。

客戶端在 `rev` 與自己持有的修訂號不同時拉一次文件，寫進 IndexedDB，在裝置上算固態分。每條除以 5 得到 0 到 1 的因子，權重來自 [`room-scoring.md`](../room-scoring.md)，分數當天每個窗口複用。一個修訂號對應一次拉取。

資料集只用於排序和卡片上的那句話。卡片上寫「安靜，座位有插座」。原始分值留在客戶端裡。

## 後果

一把尺子，一個順序。持有 `rev` 14 的兩個客戶端，對同一個窗口、同一份畫像，把同樣的房間排成同樣的順序。出現分歧時，來源是畫像或可用性快照，兩者都可以查。

資料集需要一套審計流程。每個修訂號帶作者、日期和變動房間的清單。改一條數值就是改一條記錄並遞增 `rev`，修訂號就是追問「誰在什麼時候改了這間房」的把手。

客戶端多一個快取層：一個 IndexedDB 儲存、啟動時比對修訂號、不一致時重拉、新修訂號落地後本地重算固態表。

新房間上線前要有六條屬性。審計是上線流程的一部分，沒有記錄行的房間不進候選集。

兩次審計之間，數值描述的是過去的樓。一層樓裝修後仍用舊值，直到下一次審計，`updatedAt` 說明這份描述有多舊。

每條數值是一次判斷。它是審計員在一次走訪裡看到的現場，修訂號是這份資料能支撐的唯一新鮮度宣告。

數值錯一個，代價是一次排序偏差。學生自己的「換一間」可以壓過去，單條數值不具破壞性。

## 備選方案

**每個客戶端自己給房間打分。** 已否決。同一間房在兩臺手機上排位不同，候選順序失去可比性。N 個客戶端還把一次審計複製成 N 份判斷。

**服務端直接下發算好的固態分。** 每間房一個浮點數，拿來就排。已否決。學生問「為什麼」時浮點數答不出東西，權重也會搬到服務端，改一次權重變成一次部署。

**屬性跟著每次可用性請求一起下發。** 已否決。可用性每個窗口問一次，一天最多八次，屬性一學期變一次。每次請求都為了攜帶一份一年動四次的文件而變大。

**從課表推斷房間質量。** 一間用來上課的教室，在空著的日子裡算安靜。已否決。一個學期的佔用情況說不出桌面、插座和採光，沒人去過的房間錯得最狠。

**從評價推斷房間質量。** 暫時否決。評價到得不均勻，熱門房間收到三十條，其餘一條也沒有，沒有評價的房間會跟差評房間同分。
