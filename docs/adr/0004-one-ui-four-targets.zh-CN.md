# 0004. 一个 UI，四个交付目标

[English](0004-one-ui-four-targets.md) · **简体中文** · [繁體中文](0004-one-ui-four-targets.zh-TW.md)

- Status: Accepted
- Date: 2026-11-04
- Scope: `web/`, `capacitor/`, `docs/architecture.md`

## 背景

NextStop 从四个地方被访问。书桌上的浏览器，走廊里的手机，用于演示的 Android 手机，以及同一场演示的 iPhone。这四个背后是同一个界面：一张卡片承载下一件要做的事，下面是一叠时段块，三个标签页，四个动作。一张卡片，一个时间，一个目的地。

这个界面很普通。列表、卡片、表单、表格、一条时间轴。它从数据层读取 JSON 答案，然后画出一份计划。它里面没有任何东西需要原生绘制、原生手势，或者浏览器引擎撑不住的帧预算。它不是游戏，也不是相机。

它也已经写好了。Vue 3 加 Vite，一棵组件树，一套样式，客户端一份规划规则副本。第二套实现的代价不在第一个屏幕。它是每一个屏幕，两遍，永远，用两种语言，对同一个问题给出两个答案。

物理事实决定其余部分。走廊没有信号，所以手机必须在无网络下打开。学生不该被迫输入 URL，所以手机构建必须能安装到主屏幕。两个移动平台都存在，而课程演示必须两个都能跑。

[`architecture.md`](../architecture.md) 第 6 节描述了两次 Vite 构建，一个桌面版和一个手机版，共享一份契约。那次拆分关乎布局，不关乎平台。本记录确定存在几套实现，以及几个容器加载它们。

## 决策

一个 Vue 3 加 Vite 前端。`vite build` 写出 `dist/`。那个目录就是产品。

四个交付目标加载它：

- **浏览器。** `dist/` 作为静态文件提供。基线，也是其他一切回退到的形态。
- **PWA。** 同一个 `dist/`，加上一份 manifest 和一个 service worker。可安装到主屏幕，并且能在无网络下打开。
- **Android 外壳。** Capacitor 把 `dist/` 复制进一个原生工程并产出 APK。
- **iOS 外壳。** 同一个 Capacitor 工程，第二个平台目录，以及一个 IPA。

Capacitor 把这次构建包进一个原生容器。它不改写 UI。它给 webview 一个全屏、一个包名、一个应用图标，以及一个通往我们需要的少数原生调用的桥，比如状态栏颜色和返回键处理。四个目标运行同一份 JavaScript、同一批组件、同一份 CSS。

第 6 节所描述的两个客户端，变成一个构建加两套由断点选择的布局。关于权限的一切都没有搬进客户端。数据层依然决定谁可以改房间使用时间，界面只能提供它被允许做的事。

每个控件只有一套实现。一个屏幕不能因为省略而在目标之间产生差异。如果按钮在桌面上存在，它在手机上以同一份代码存在，差异要么是一条 CSS 规则，要么是一次能力检查，绝不是屏幕的分叉。

## 后果

一次修复触达四个目标。一个修好的登录表单在浏览器、PWA 和两个外壳里同时修好，因为它们加载同一份产物。

所有目标一起发布。`/api/about` 里的版本字符串、service worker 的缓存名和两个外壳构建都来自同一个 `package.json`，所以它们不可能不一致。

离线是继承来的，不是添加的。因为计划住在客户端（[ADR 0002](0002-plan-lives-in-the-client.zh-CN.md)），这一天已经是本地状态。service worker 缓存外壳和最近一次可用性答案，走廊场景就能工作。没有为 PWA 单独写离线功能。

控件不是原生的，有两种行为必须用 CSS 处理。滚动惯性和键盘行为属于浏览器，不属于平台。`overscroll-behavior` 阻止页面回弹，视觉视口被监听，以免聚焦的输入框被键盘遮住。

安全区域需要显式内边距。刘海、圆角和底部手势条压在 webview 上方。布局用 `env(safe-area-inset-top)`、`env(safe-area-inset-bottom)` 以及它们的左右兄弟值给自己加内边距，视口 meta 带上 `viewport-fit=cover`，让这些值非零。

iOS 分发是最贵的角落。真机需要 Mac、Xcode 和付费开发者账号，所以课程演示在模拟器里跑。Android 没有这道墙，APK 通过侧载安装。

webview 是共享运行时，所以引擎里的一个 bug 在两个手机平台上都是 bug。一个重屏幕在老旧 Android 手机上和浏览器里一样贵，这里没有任何东西能让它更便宜。

桥是新的接口面。每个插件都是按平台的原生代码，所以一项原生能力就是一小段写两遍的碎片，即使 UI 只写一遍。

## 备选方案

**React Native 或 Expo。** 真正的原生控件，庞大的生态，在线更新。已否决。渲染层不同，所以现有的 Vue 组件和样式要改写成 React，新实现还要遵守与已测试的那套不同的一套规则。它还会替代浏览器目标，而不是与之并存。

**Flutter。** 一套代码库，一个渲染器，两个手机和浏览器里画面一致。已否决。它需要 Dart。每个屏幕和每条共享规划规则都要搬到第二种语言，而 Web 目标会变成一个画布而不是文档，代价是我们本来免费获得的可访问性与文本选择。

**Tauri 2 移动端。** 小体积二进制，Rust 内核，一个本可以保留我们组件的 webview 前端。已否决。移动那一半还很年轻，插件生态很薄，而课程需要两个可上架的包，不是一个实验。

**Kotlin Multiplatform 加 Compose Multiplatform。** 共享逻辑与共享 UI，对 Android 有很强的叙事。已否决。它需要 Kotlin 和一次 Compose 改写，而且它不给桌面演示所依赖的浏览器目标。

**两个手写原生应用。** 每个平台上最好的手感。已否决。一个界面三套实现，三个计划 bug 可以藏身的地方，以及一个不允许这样做的进度表。
