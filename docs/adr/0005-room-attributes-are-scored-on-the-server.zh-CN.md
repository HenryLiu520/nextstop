# 0005. 房间属性在服务端打分

[English](0005-room-attributes-are-scored-on-the-server.md) · **简体中文** · [繁體中文](0005-room-attributes-are-scored-on-the-server.zh-TW.md)

- Status: Accepted
- Date: 2026-11-11
- Scope: 房间属性端点、评分层、`docs/room-scoring.md`

## 背景

自习室推荐要在一个窗口里给房间排序。排序有两部分。动态部分读窗口、读从上一个停靠点走过来的时间、读走到下一个停靠点的时间。固态部分描述房间本身：有多安静，桌面放不放得下电脑和书，座位旁边有没有电。

固态部分属于房间。它落在计划之外，也落在可用性答案之外。可用性告诉你 2A 在 10:00 到 11:00 是空的。它说不出 2A 里有多吵，也说不出墙边有没有插座。同一个窗口里空着的两间房，差别可以是整个决定。

客户端能读可用性，能据此算出占用。同一个客户端没有来源知道门边是电梯厅、桌面只有 60 厘米宽、窗朝天井。这些事实来自走一趟楼、一张平面图，或者物业办公室。

排序还需要同一把尺子。同一个窗口里的两位学生比较的是同样的 200 间房。每台手机自己打分，就得到自己的顺序，一间房在一台设备上排第一、在另一台上排第四，候选列表就不再是一个答案。

## 决策

后端提供房间属性：每间房六个维度，每条是 0 到 5 的整数，装在一份带修订号的文档里。

```
GET /v1/rooms/attributes
{ "rev": 14,
  "updatedAt": "2026-11-11T09:00:00Z",
  "rooms": [ { "code": "KB227", "quiet": 4, "desk": 3, "sockets": 3,
               "ac": 5, "spaciousness": 4, "daylight": 3 } ] }
```

每个维度在 0、3、5 各有一个锚点。审计员走进房间，写下与它相符的整数。

| 维度 | 键 | 0 | 3 | 5 |
|---|---|---|---|---|
| 安静度 | `quiet` | 门朝电梯厅、食堂或人流不断的走廊 | 开放区，旁边一桌在说话 | 门内的静音区，远离人流 |
| 桌面与座位 | `desk` | 沙发或长凳，没有书写平面 | 共用长桌，放得下电脑和一本书 | 独立桌面，宽 90 厘米以上，配椅子 |
| 插座密度 | `sockets` | 没有可用插座 | 沿墙有插座 | 每个座位都有插座 |
| 空调 | `ac` | 没有空调 | 空调按楼宇时间表开关 | 房间内有控制面板的空调 |
| 空间 | `spaciousness` | 每个座位 1.0 平方米以下，桌子连排 | 每个座位约 2.0 平方米 | 每个座位 3.0 平方米以上，多数桌子旁边有空位 |
| 采光 | `daylight` | 无窗 | 窗朝天井或内院 | 外窗，自然光照到桌面 |

1、2、4 用来记落在两行之间的房间。审计员写下与房间相符的整数，安静度上的 2 表示比食堂安静、比开放区吵。

客户端在 `rev` 与自己持有的修订号不同时拉一次文档，写进 IndexedDB，在设备上算固态分。每条除以 5 得到 0 到 1 的因子，权重来自 [`room-scoring.md`](../room-scoring.md)，分数当天每个窗口复用。一个修订号对应一次拉取。

数据集只用于排序和卡片上的那句话。卡片上写「安静，座位有插座」。原始分值留在客户端里。

## 后果

一把尺子，一个顺序。持有 `rev` 14 的两个客户端，对同一个窗口、同一份画像，把同样的房间排成同样的顺序。出现分歧时，来源是画像或可用性快照，两者都可以查。

数据集需要一套审计流程。每个修订号带作者、日期和变动房间的清单。改一条数值就是改一条记录并递增 `rev`，修订号就是追问「谁在什么时候改了这间房」的把手。

客户端多一个缓存层：一个 IndexedDB 存储、启动时比对修订号、不一致时重拉、新修订号落地后本地重算固态表。

新房间上线前要有六条属性。审计是上线流程的一部分，没有记录行的房间不进候选集。

两次审计之间，数值描述的是过去的楼。一层楼装修后仍用旧值，直到下一次审计，`updatedAt` 说明这份描述有多旧。

每条数值是一次判断。它是审计员在一次走访里看到的现场，修订号是这份数据能支撑的唯一新鲜度声明。

数值错一个，代价是一次排序偏差。学生自己的「换一间」可以压过去，单条数值不具破坏性。

## 备选方案

**每个客户端自己给房间打分。** 已否决。同一间房在两台手机上排位不同，候选顺序失去可比性。N 个客户端还把一次审计复制成 N 份判断。

**服务端直接下发算好的固态分。** 每间房一个浮点数，拿来就排。已否决。学生问「为什么」时浮点数答不出东西，权重也会搬到服务端，改一次权重变成一次部署。

**属性跟着每次可用性请求一起下发。** 已否决。可用性每个窗口问一次，一天最多八次，属性一学期变一次。每次请求都为了携带一份一年动四次的文档而变大。

**从课表推断房间质量。** 一间用来上课的教室，在空着的日子里算安静。已否决。一个学期的占用情况说不出桌面、插座和采光，没人去过的房间错得最狠。

**从评价推断房间质量。** 暂时否决。评价到得不均匀，热门房间收到三十条，其余一条也没有，没有评价的房间会跟差评房间同分。
