# 0001. 后端是数据层

[English](0001-backend-is-the-data-layer.md) · **简体中文** · [繁體中文](0001-backend-is-the-data-layer.zh-TW.md)

- Status: Accepted
- Date: 2026-11-04
- Scope: `backend/`, `db/`, both clients' API surface

## 背景

NextStop 只回答一个问题：这个人应该在哪里，以及应该在什么时候移动。
这个答案可以在服务端计算，也可以在客户端计算。这个选择决定了后端的存在意义。

系统所需的事实并不是同一类东西。

| 属性 | 计划 | 课表 |
|---|---|---|
| 所有者 | 一名学生 | 学校机构 |
| 生命周期 | 一天 | 一个学期 |
| 变更频率 | 每次会话多次编辑 | 发布后即固定 |
| 真值 | 一份提案，始终可协商 | 最终结果，不容置疑 |
| 读写 | 本地可读可写 | 我方只读 |

课表由数千人共享，由本项目无法控制的教务办公室发布，并且在整个学期内为真。计划属于一个人，到明天就失效。
这是两个不同的问题，它们需要两个不同的归属。

同一个房间这个事实，不能因为看的人是两位而不同。如果桌面客户端和手机客户端对 2A 在 10:00 到 11:00 是否被占用存在分歧，系统里没有任何东西能裁决这场争论。课表必须有一个唯一权威，而计划不需要这样的权威。

## 决策

后端是数据层。它回答「我能去哪里」。

它提供课表、房间、建筑、可用性、管理员房间更新、评价、账号和审计日志。它运行在 Spring Boot 4.1.1 与 Java 21 之上，数据库为 PostgreSQL 17，Flyway 迁移从 V1 到 V16。

它不存储任何计划。没有 plans 表，没有接受计划的端点，也没有任何列用来存放计划。服务器对学生 14:00 应该在哪里没有任何意见。

可用性计算保留在服务端，因为这是两个客户端必须一致认同的那一个答案：

```
free(room, date) = blocks(room, date)
                 - blocks taken by a class
                 - blocks taken by an active room update
                 - 10 minutes either side of every occupied block
```

切换余量是服务端配置，默认 10 分钟，永远不是客户端设置。课表优先于管理员备注：与上课时段重叠的更新会被拒绝，返回 HTTP 400 与错误码 `TIMETABLE_PRIORITY`。

角色顺序为 `user < admin < superadmin`，只在服务端强制执行一次。客户端只隐藏令牌无权使用的东西。

## 后果

共享事实只有一个归属。两个不同版本的客户端不可能对同一个房间产生分歧，而对于我方只读的数据，也不需要任何冲突解决。

规划规则可以在不做迁移的情况下改变。新的站点类型、新的间隔规则、新的修复优先级都是客户端改动。数据库模式不追踪计划的形状，所以计划变化时它永远不必跟着变。

服务保持小巧并且可测试。它的接口面就是一个问题加上管理功能，27 个针对真实数据库的自动化测试覆盖了它。

代价是服务器无法回答某个用户在 14:00 在做什么。任何需要这个答案的功能，从共享计划到提醒，都必须在客户端实现，或者需要一个新的决策。

多设备同步是另一件事。没有存储的计划就没有同步，没有版本列，也没有 last-write-wins 规则。它也意味着完全没有答案，在功能存在之前，这是诚实的立场。

计划质量对服务器不可见。四个成功指标只在客户端埋点，所以中心化度量需要一条显式的上报路径。

可用性是一个快照。客户端在揭示时读取它，服务端不轮询，之后变满的房间会留在计划里，直到用户自己上报。这一点被接受，并未被解决。

## 备选方案

**服务端持有计划。** 一张 plans 表，配套读写端点。已否决。它需要一个用户、一个版本、一条同步规则和一套冲突叙事，而且它依然输给一台没保存就关机的手机。代价是协调，而计划寿命太短，付不起。

**薄后端加客户端课表。** 课表只发一次，让每个客户端自己计算可用性。已否决。同一个共享真值有两套实现，跑在两个发布周期上，没有仲裁者。光切换余量就会在两者之间漂移。

**面向前端的后端，每个客户端一套端点。** 已否决。两个客户端共享一份契约更便宜，而按客户端划分的接口面只是掩盖分歧，并不能阻止分歧。

**把后端做成产品。** 规划端点、已保存的日子、会话、服务端推荐。已否决。产品的核心主张是系统来决定这一天，而服务器无法决定一个它看不见用户在其中的日子。它还会把有意思的逻辑推到网络边界和一次部署之后。

**作为便利的计划缓存。** 为每个用户存下最后一次计划，方便第二台设备接上。暂时否决。它为一个只有一天寿命的文档在服务端增加了写入路径，而它服务的唯一用户是那种中午换了设备的人。
