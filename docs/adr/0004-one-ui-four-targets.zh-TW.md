# 0004. 一個 UI，四個交付目標

[English](0004-one-ui-four-targets.md) · [簡體中文](0004-one-ui-four-targets.zh-CN.md) · **繁體中文**

- Status: Accepted
- Date: 2026-11-04
- Scope: `web/`, `capacitor/`, `docs/architecture.md`

## 背景

NextStop 從四個地方被訪問。書桌上的瀏覽器，走廊裡的手機，用於演示的 Android 手機，以及同一場演示的 iPhone。這四個背後是同一個介面：一張卡片承載下一件要做的事，下面是一疊時段塊，三個標籤頁，四個動作。一張卡片，一個時間，一個目的地。

這個介面很普通。列表、卡片、表單、表格、一條時間軸。它從資料層讀取 JSON 答案，然後畫出一份計劃。它裡面沒有任何東西需要原生繪製、原生手勢，或者瀏覽器引擎撐不住的幀預算。它不是遊戲，也不是相機。

它也已經寫好了。Vue 3 加 Vite，一棵元件樹，一套樣式，客戶端一份規劃規則副本。第二套實現的代價不在第一個螢幕。它是每一個螢幕，兩遍，永遠，用兩種語言，對同一個問題給出兩個答案。

物理事實決定其餘部分。走廊沒有訊號，所以手機必須在無網路下開啟。學生不該被迫輸入 URL，所以手機構建必須能安裝到主螢幕。兩個移動平臺都存在，而課程演示必須兩個都能跑。

[`architecture.md`](../architecture.md) 第 6 節描述了兩次 Vite 構建，一個桌面版和一個手機版，共享一份契約。那次拆分關乎佈局，不關乎平臺。本記錄確定存在幾套實現，以及幾個容器載入它們。

## 決策

一個 Vue 3 加 Vite 前端。`vite build` 寫出 `dist/`。那個目錄就是產品。

四個交付目標載入它：

- **瀏覽器。** `dist/` 作為靜態檔案提供。基線，也是其他一切回退到的形態。
- **PWA。** 同一個 `dist/`，加上一份 manifest 和一個 service worker。可安裝到主螢幕，並且能在無網路下開啟。
- **Android 外殼。** Capacitor 把 `dist/` 複製進一個原生工程併產出 APK。
- **iOS 外殼。** 同一個 Capacitor 工程，第二個平臺目錄，以及一個 IPA。

Capacitor 把這次構建包進一個原生容器。它不改寫 UI。它給 webview 一個全屏、一個包名、一個應用圖示，以及一個通往我們需要的少數原生呼叫的橋，比如狀態列顏色和返回鍵處理。四個目標執行同一份 JavaScript、同一批元件、同一份 CSS。

第 6 節所描述的兩個客戶端，變成一個構建加兩套由斷點選擇的佈局。關於許可權的一切都沒有搬進客戶端。資料層依然決定誰可以改房間使用時間，介面只能提供它被允許做的事。

每個控制元件只有一套實現。一個螢幕不能因為省略而在目標之間產生差異。如果按鈕在桌面上存在，它在手機上以同一份程式碼存在，差異要麼是一條 CSS 規則，要麼是一次能力檢查，絕不是螢幕的分叉。

## 後果

一次修復觸達四個目標。一個修好的登入表單在瀏覽器、PWA 和兩個外殼裡同時修好，因為它們載入同一份產物。

所有目標一起釋出。`/api/about` 裡的版本字串、service worker 的快取名和兩個外殼構建都來自同一個 `package.json`，所以它們不可能不一致。

離線是繼承來的，不是新增的。因為計劃住在客戶端（[ADR 0002](0002-plan-lives-in-the-client.zh-TW.md)），這一天已經是本地狀態。service worker 快取外殼和最近一次可用性答案，走廊場景就能工作。沒有為 PWA 單獨寫離線功能。

控制元件不是原生的，有兩種行為必須用 CSS 處理。滾動慣性和鍵盤行為屬於瀏覽器，不屬於平臺。`overscroll-behavior` 阻止頁面回彈，視覺視口被監聽，以免聚焦的輸入框被鍵盤遮住。

安全區域需要顯式內邊距。劉海、圓角和底部手勢條壓在 webview 上方。佈局用 `env(safe-area-inset-top)`、`env(safe-area-inset-bottom)` 以及它們的左右兄弟值給自己加內邊距，視口 meta 帶上 `viewport-fit=cover`，讓這些值非零。

iOS 分發是最貴的角落。真機需要 Mac、Xcode 和付費開發者帳號，所以課程演示在模擬器裡跑。Android 沒有這道牆，APK 透過側載安裝。

webview 是共享執行時，所以引擎裡的一個 bug 在兩個手機平臺上都是 bug。一個重螢幕在老舊 Android 手機上和瀏覽器裡一樣貴，這裡沒有任何東西能讓它更便宜。

橋是新的介面面。每個外掛都是按平臺的原生程式碼，所以一項原生能力就是一小段寫兩遍的碎片，即使 UI 只寫一遍。

## 備選方案

**React Native 或 Expo。** 真正的原生控制元件，龐大的生態，線上更新。已否決。渲染層不同，所以現有的 Vue 元件和樣式要改寫成 React，新實現還要遵守與已測試的那套不同的一套規則。它還會替代瀏覽器目標，而不是與之並存。

**Flutter。** 一套程式碼庫，一個渲染器，兩個手機和瀏覽器裡畫面一致。已否決。它需要 Dart。每個螢幕和每條共享規劃規則都要搬到第二種語言，而 Web 目標會變成一個畫布而不是文件，代價是我們本來免費獲得的可訪問性與文字選擇。

**Tauri 2 移動端。** 小體積二進位制，Rust 核心，一個本可以保留我們元件的 webview 前端。已否決。移動那一半還很年輕，外掛生態很薄，而課程需要兩個可上架的包，不是一個實驗。

**Kotlin Multiplatform 加 Compose Multiplatform。** 共享邏輯與共享 UI，對 Android 有很強的敘事。已否決。它需要 Kotlin 和一次 Compose 改寫，而且它不給桌面演示所依賴的瀏覽器目標。

**兩個手寫原生應用。** 每個平臺上最好的手感。已否決。一個介面三套實現，三個計劃 bug 可以藏身的地方，以及一個不允許這樣做的進度表。
